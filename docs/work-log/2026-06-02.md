## #39 — Another session's output leaking and printing a wrong prompt at the top on new-tab connect

### What / Why / How
- Symptom: connecting SSH in a new tab from the host list prints another server/session's prompt at the top, followed by the new server banner (e.g., `cuter74@testllm:~$` shown in the mscllm new tab). The true root cause of the long-tracked "leftover top prompt."
- Cause: `ssh:output`/`pty:output` are **global events shared by all sessions**. `Terminal`'s output listener filter was `if (sessionId && payload.session_id !== sessionId) return`, so before the new tab's spawn finished (`sessionId === null`) the condition was false and **another active session's output got written into this terminal**. As it happened, Claude Code was actively printing in another tab, so its prompt leaked at the top of the new tab.
- Fix: change the filter to `if (!sessionId || payload.session_id !== sessionId) return` — write nothing before sessionId is set. `sessionId = await invoke(spawnCmd...)` is a synchronous assignment right after await (event callbacks run in later tasks), so no loss of the own session's banner/output.

### Notes
- Previously the "top prompt" was blamed on OSC 7 injection and the injection was removed (#37), but that was a side branch; the actual root cause was this global output filter bug. (Removing OSC 7 injection is kept separately — cwd sync is guided via a ~/.bashrc hook.)

## #40 — Screen broken at a very narrow width on tmux reattach (hidden tab fits to 0)

### What / Why / How
- Symptom: with multiple testllm tabs attached to the same remote tmux session, the tmux content (Claude Code) wraps at ~10 columns and looks broken vertically.
- Cause: a background (hidden) tab is display:none → container 0-size. The `ResizeObserver` then calls `fit()` → cols/rows shrink to the minimum (~2) and are sent to the remote PTY. tmux fits to the **smallest** attached client, so one hidden tab's tiny size shrinks the whole shared session.
- Fix: introduce `safeFit()` — fit only when container `clientWidth/Height >= 8`. Applied at: initial fit, ResizeObserver, finishAttach (guards subsequent resize too), the settings-change effect, the registered `fit()` method.
- Mitigation (remote, recommended): tmux `set -g window-size latest` to fit the most recently active client instead of the smallest.

### Recovering an already-broken session
- Close leftover testllm tabs to reduce clients, or focus each tab once to refit, or `tmux resize-window -A` in tmux.

## #42 — Terminal Tab key moving focus to the AI panel

### What / Why / How
- Symptom: pressing Tab in the terminal sometimes moves focus to the AI assistant area.
- Cause: the Tab branch when an inline autocomplete suggestion is showing only did `return false` without `e.preventDefault()` → xterm doesn't process it but the browser's default Tab (focus traversal) still runs, moving to the next focus target (the AI panel textarea). When there was no suggestion, xterm handled it and preventDefault'd so it didn't leak — hence it looked "occasional."
- Fix: comprehensively handle Tab (no metaKey/ctrlKey/altKey) in `customKeyEventHandler` — always `e.preventDefault()`. Accept the suggestion if present; otherwise send `\t` to the shell (Shift+Tab → back-tab `\x1b[Z`) and return false. Block focus move at the source.
