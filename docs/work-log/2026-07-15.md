# 2026-07-15

## #133 — 한글 자모가 따로 입력됨: 낡은 compositionMachine 래치 자가 복구

### What / Why
- macOS 한글 입력 시 자모가 조합되지 않고 하나씩 따로 찍히는 제보. **현장 진단 데이터로 원인 확정** — GlitchTip `wt-ime-diag2` 이벤트 99건(release 0.20.6)에서 `n229=62`인데 `nCS/nCU/nCE=0`, `mirrorChars=0`.
- 해석: 그 머신이 **229-only(Type A) 동작으로 회귀**했는데(macOS 업데이트/입력 소스 변경으로 발생), 과거에 저장된 래치 `localStorage["wt.ime.cmp"]=1`이 "이 머신은 composition 머신(Type B)"이라고 못 박아 **커스텀 IME 미러를 영구히 꺼둔 상태**였다. 결국 자모를 조합해 줄 주체가 아무도 없었다.
- #100에서 도입한 래치는 한 번 서면 되돌아오지 못하는 편도(one-way)였다는 게 문제. 자가 복구 경로가 필요했다.

### How
- `src/components/Terminal.tsx`에 세션 단위 휴리스틱 추가:
  - `csSeenSession` — 이 세션에서 `compositionstart`가 한 번이라도 발생하면 true. 건강한 조합 머신은 **첫 자모에서 반드시 CS가 오므로** 그 즉시 휴리스틱이 비활성화된다(오탐 차단).
  - `stale229` — CS가 한 번도 없는 상태에서 인쇄형 keyCode-229 keydown을 센다. **Backspace는 제외** — 정상 조합 머신도 한글 삭제 시 229를 내므로 카운트에 넣으면 오탐한다.
  - `healStaleCompositionLatch()` — 임계치(4회) 도달 시 `compositionMachine=false`, `localStorage`의 `wt.ime.cmp` 제거, `body.wt-native-ime` 클래스 해제 → **그 키스트로크부터 미러가 다시 개입**한다.
- macOS(`isMacWebView`)에서만 동작 — Windows/Linux는 네이티브 IME 경로라 건드리지 않는다(#84/#88 회귀 방지 원칙).
