# 2026-10-19

## #154 — 원격 세션 출력이 복사되지 않는 문제 (macOS)

**증상**: 원격으로 접속한 서버의 출력이 **복사되지 않는다**. 드래그를 해도 선택 하이라이트가 전혀 생기지 않고, `⌘C`나 우클릭 → Copy도 아무 일도 하지 않는다. 로컬 셸에서는 멀쩡하다가 특정 프로그램(tmux 마우스 on, vim, htop, Claude Code/Gemini TUI)을 띄우면 같은 증상이 난다.

**원인(정확히)**: 클립보드 쪽 문제가 아니라 **선택 자체가 시작되지 않는 것**. 설치된 `@xterm/xterm` 6.0.0 번들에서 확인:

```js
if (coreMouseService.areMouseEventsActive && !selectionService.shouldForceSelection(e))
  return sendMouseEventToApp(e);

shouldForceSelection(e) {
  return isMac ? e.altKey && rawOptions.macOptionClickForcesSelection
               : e.shiftKey;
}
// 기본값: macOptionClickForcesSelection: false
```

앱이 마우스 트래킹(DECSET 1000/1002/1003)을 켜면 mousedown이 전부 앱으로 넘어가고, 빠져나가는 유일한 경로가 `shouldForceSelection`이다. 그런데 **macOS 분기는 `altKey && macOptionClickForcesSelection`** 이고 이 앱은 그 옵션을 설정하지 않아 기본값 `false` — 조건이 영원히 거짓이라 **macOS에는 탈출 제스처가 하나도 없었다**. Windows/Linux는 `shiftKey` 분기라 옵션 없이도 `Shift`+드래그가 동작했다. 선택이 없으니 `hasSelection()`이 false이고, 복사 경로는 전부 선택 문자열을 읽으므로 조용히 아무 것도 복사하지 않는다.

"원격에서만" 보이는 이유는 마우스 리포팅을 켜는 프로그램이 주로 원격에서 돌기 때문이고, 전송 계층(SSH)과는 무관하다. xterm 타입 정의의 설명도 정확히 이 용도를 명시한다 — *"this allows you to use xterm.js' regular selection inside tmux with mouse mode enabled."*

**수정**: `src/components/Terminal.tsx`의 xterm 생성 옵션에 `macOptionClickForcesSelection: true` 추가 (한 줄 + 근거 주석). → **⌥(Option)+드래그**로 마우스 리포팅을 무시하고 로컬 선택이 된다. Terminal.app·iTerm2와 같은 관례.

**무회귀 근거**: 이 분기는 `areMouseEventsActive`가 참일 때만 타므로, 마우스 리포팅이 꺼진 평소에는 코드 경로가 바뀌지 않는다. `altClickMovesCursor`(⌥+클릭으로 커서 이동, 기본 true)는 마우스 이벤트가 비활성일 때만 동작하는 별개 경로라 영향 없다.

**검증**: 클린 로컬 사본(`npm ci`)에서 `npx tsc --noEmit` 무오류 — 옵션명이 6.0.0 타이핑에 실재함을 확인. `npx vite build` 성공(429 modules), 번들에 `macOptionClickForcesSelection`가 들어간 것까지 확인.

**문서**: `docs/guide/shortcuts.md`의 Mouse 절에 "앱이 마우스를 쓰는 중에 텍스트 선택하기"(macOS `⌥`, Windows/Linux `Shift`) 항목 추가.

### 작업 환경 메모
Synology Drive가 꺼진 상태에서 dataless(클라우드 전용) 파일은 materialize가 불가능해 `mmap: Resource deadlock avoided`로 실패한다. `git diff`(전체), `rsync`, `cp -R`가 여기서 멈췄다 — `node_modules`에 2,724개, `src`에 1개(`SessionDashboard.tsx`)가 dataless였다. 해결: 소스만 로컬로 복사하고 dataless 파일은 `git show HEAD:<path>`로 복원, `node_modules`는 `npm ci`로 새로 받아 빌드/타입체크를 로컬 디스크에서 수행. 파일 단위 `git diff -- <path>`는 정상 동작한다.
