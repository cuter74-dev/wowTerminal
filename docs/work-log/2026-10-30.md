## #160 — 세션 데몬 2단계: SSH 세션도 업데이트·재시작에 유지

### 설계
- 대화형 흐름(호스트 키 확인·비밀번호)은 원래 **요청/응답**이다(`ssh_connect`가 구조화된 오류로 실패 → UI 모달 →
  재호출). 그래서 데몬에 "터널링"할 필요 없이 같은 오류를 그대로 돌려주면 된다.
- 인증은 UI가 해석한다(시크릿 저장소·비밀번호 프롬프트) → `WireAuth`(비밀번호 또는 키 원문)로 데몬에 전송.
  **데몬은 시크릿 저장소를 열지 않는다.** 소켓은 0600(같은 사용자만). 호스트 키 저장소는 매 확인마다 파일을
  다시 읽으므로 UI·데몬이 같은 파일을 공유.
- 프로토콜 v2(append-only): SshConnect/Write/Resize/Kill/RemoteCwd/TmuxSessions/ProbeSystem, MarkDetached,
  Shutdown, 이벤트 SshOutput. 재attach는 `ssh_connect`의 `attach` 힌트 — 데몬에 살아 있으면 인증 없이 반환.

### 버전 스큐 (가장 신경 쓴 부분)
- 업데이트 직후엔 **구버전(v1) 데몬이 살아 있다.** v1은 모르는 op에 id 0으로 답해 요청이 **영영 응답을 못 받는다**
  → UI는 hello의 프로토콜이 2 이상일 때만 SSH를 데몬으로 보낸다. 새 데몬은 해석 실패 요청에도 원래 id로 답한다.
- v1은 앱이 붙어 있는 한 유휴 종료가 오지 않아 **기존 사용자에겐 SSH 유지가 영영 안 켜질 뻔했다.**
  `connect_current`: 구버전 데몬이 **세션 0개**면 교체 — v2+는 Shutdown, v1은 소켓 상대 pid(LOCAL_PEERPID)의
  명령줄이 `--daemon --socket <이 소켓>`인지 확인한 뒤에만 SIGTERM. **세션이 있으면 그대로 둔다**(실행 중인 셸 보호).
- 데몬 종료 시 소켓 파일은 **inode가 자기 것일 때만** 삭제(다음 데몬 소켓을 지우는 경합 방지).

### 함께 찾은 #153(1단계) 버그 2개
- 탭 분리 보호 표시가 인프로세스 매니저에만 가고 kill은 데몬으로 가서, **탭 분리 시 세션이 죽을 수 있었다** →
  `MarkDetached`를 데몬으로.
- 복원 시 살아 있던 세션에 재attach됐는데도 **저장된 `tmux attach`를 입력해** 실행 중인 프로그램에 글자가 들어갔다 → 건너뜀.

### 검증
- 데몬 통합 테스트(CI): 프로토콜 2, 소켓 0600, MarkDetached 보호, 모르는 op의 응답 id, SSH 접속 실패가 구조화 오류.
- 무시(ignored) e2e(로컬 실행):
  - 실제 SSH 서버(asyncssh 테스트 서버)로 접속 → 클라이언트 종료 → 새 클라이언트가 같은 세션 id로: 서버에
    **새 접속 없음**, 같은 원격 셸에 두 클라이언트 입력이 모두 도착, 스크롤백 복원.
  - **설치된 0.20.19 바이너리를 v1 데몬으로** 띄워: 세션 없으면 교체(프로토콜 2, 옛 프로세스 종료), 셸이 있으면 유지.
- 변이: 모르는 op 응답을 id 0으로 되돌리면 테스트 실패.
- **미검증**: 실제 앱 UI 재시작 e2e — macOS Unix 소켓 경로 104바이트 제한 때문에 작업 폴더 아래로 격리 HOME을
  둘 수 없었다(`/tmp` 필요). 프론트 재attach 경로는 1단계와 공용이고 변경은 `attach` 인자 한 줄.
- clippy 경고 수 변화 없음(17), cargo test 57(+3 ignored), npm test 23.

## #165 — 빠른 편집 팝업이 파일을 자르거나 깨뜨림 / 터미널 드롭이 덮어씀

### 원인
- 편집 팝업은 `read_text`로 **앞 256KB만 lossy UTF-8**로 읽는데 항상 편집 가능으로 열렸다. 저장은 truncate 후
  그 내용을 쓰므로 256KB 뒤가 사라졌다. ⌘S는 `dirty` 검사 없이 저장 → 열기만 하고 ⌘S만 눌러도 잘림.
- 비UTF-8·바이너리는 U+FFFD로 바뀌어 저장됐고, textarea가 CRLF·CR을 LF로 정규화해 CRLF 파일이 LF가 됐다.
- 저장 후에도 기준이 원래 prop이라 `dirty`가 계속 참("저장됨"이 안 보임).
- 터미널 드롭: SSH는 `sftp_upload`가 create(truncate), 로컬은 `std::fs::copy` — 확인 없이 덮어씀.
  copy는 대상이 심볼릭 링크면 링크 너머에 쓴다.

### 수정
- `ssh/textfile.rs`의 `classify`: 상한+1바이트를 읽어 `too_large` / `binary`(NUL) / `not_utf8` / `mixed_eol`이면
  읽기 전용 + 이유. 순수 CRLF면 `eol: "crlf"`. 새 명령 `sftp_read_for_edit`·`local_read_for_edit`
  (`local_read_text`는 설정 가져오기가 쓰므로 그대로 둠, `sftp_read_text`는 사용처가 팝업뿐이라 대체).
- 프런트: 저장·변경 비교 모두 `toFileEol`(src/eol.ts)로 파일 줄끝으로 바꾼 값 사용. 저장 성공 시 기준 갱신.
  ⌘S도 `save()` 안의 dirty 검사를 거친다. 꼬리말에 이유 표시(11개 언어).
- 드롭: `sftp_upload`에 `no_clobber` → `SftpManager::free_path`가 lstat으로 빈 이름("이름 (1).확장자", 프런트
  `uniqueName`과 같은 규칙)을 찾는다. `local_copy_into`도 같은 규칙, `symlink_metadata`로 확인.
  충돌 창을 띄우는 건 끌어놓기 통합(기획서 SC-03, 2단계) 때.

### 검증
- 단위: classify 5종, numbered_name, 로컬 복사(덮어쓰기 안 함 / 끊긴 링크 너머에 안 씀), toFileEol.
- e2e(무시 테스트): asyncssh 로컬 SFTP 서버(chroot)로 `free_path`(기존 2개·끊긴 링크·없는 이름), 실제 업로드가
  고른 이름으로 가고 원본 유지, 큰 파일·CRLF 판정. 변이: lstat을 stat으로 바꾸면 실패.
  실행: `WT_TEST_SFTP_PORT=<포트> WT_TEST_SFTP_ROOT=<루트> cargo test --lib sftp_e2e -- --ignored`.

- **미검증**: 앱 UI에서 팝업을 직접 열어 보는 확인(꼬리말 문구·버튼 상태)은 하지 않았다.
