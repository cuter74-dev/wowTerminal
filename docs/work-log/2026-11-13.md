## #186 — 오류 보고에 나온 프런트 오류 (GitLab #85)

**무엇:** 지난주 오류 보고에 나온 프런트 오류 네 가지를 고쳤다.
- `crypto.randomUUID is not a function`: Chrome 92 미만 Android WebView에는 이 함수가 없다. 호스트 저장·복제·`~/.ssh/config` 가져오기·빠른 명령 추가 4곳이 폴백 없이 불러서 그 동작이 아예 실패했다. 다른 5곳은 저마다 폴백 함수를 갖고 있었다.
- macOS `NotAllowedError`: 터미널 출력 파서 → OSC 52 처리 → `clipboard.writeText` 흐름이다. WebKit은 키 입력·클릭 밖에서 온 클립보드 쓰기를 거부해서, tmux·vim·Claude Code가 OSC 52로 보낸 복사가 클립보드에 들어가지 않고 있었다.
- Android `Write permission denied`: WebView가 클립보드 쓰기 권한을 주지 않는 경우다.
- `Non-Error promise rejection … "Folder picker is not implemented"`: 0.21.7 이하 Android 폴더 선택 버튼에서 났다. #179(모바일에서 폴더 버튼 숨김)에서 이미 고쳤다.

**왜:** 앞의 셋은 오류 보고만 쌓이는 게 아니라 실제 기능(호스트 추가, 복사)이 동작하지 않는 문제였다.

**어떻게:**
- `src/ids.ts`의 `newId()` 하나로 모았다. `randomUUID` → `getRandomValues`로 만든 UUID v4 → `Math.random` 순서로 쓴다. 중복 폴백 함수 5개도 이것으로 바꿨다.
- `src/clipboard.ts`에 `copyText()`·`readClipboard()`를 두었다. 둘 다 거부를 밖으로 던지지 않는다.
  - 쓰기는 웹 클립보드가 거부하면 Tauri 공식 `clipboard-manager` 플러그인(네이티브)으로 다시 쓴다. 권한은 `clipboard-manager:allow-write-text` 하나만 추가했다.
  - 읽기는 네이티브로 우회하지 않는다. 사용자가 WebKit 붙여넣기 확인을 닫은 것을 존중한다.
- AI 패널·SSH 키 화면의 "복사됨"과 파일 패널의 "경로 복사됨" 알림은 실제로 복사됐을 때만 보인다.
- 테스트: `src/ids.test.ts`, `src/clipboard.test.ts`, 권한 회귀 가드에 클립보드 플러그인 규칙을 추가했다.
- 참고: `beforeEach(() => mock.mockReset()…)`처럼 mock 함수를 반환하면 vitest가 그것을 정리 함수로 여기고 테스트 뒤에 다시 부른다. 중괄호로 감싸야 한다.

## #187 — 에이전트 상태: 입력 기다림 감지와 에이전트 목록 (GitLab #86)

**무엇:** herdr 같은 에이전트 인식 기능을 넣었다. 여러 탭에서 Claude Code·Codex·Gemini CLI를 돌릴 때 어느 것이 일하는 중인지, 답을 기다리는지, 끝났는지 한눈에 보고 그 창으로 바로 간다.
- 탭 표시: 일하는 중 ✻(기존), 답을 기다림 노란 `?`(새로). 뒤쪽 탭의 에이전트가 기다리기 시작하면 데스크톱 알림.
- 왼쪽 패널 [서버 | 파일 | **에이전트**]: 모든 창의 에이전트·상태(기다림·끝남·일하는 중·쉬는 중)·경과 시간. 기다림이 맨 위, 누르면 그 탭·창으로 이동.

**왜:** 사용자 요청("Herdr와 같은 기능을 터미널에 추가할 수 있을까?" → 1+2단계 선택). 3단계(에이전트용 CLI·소켓 API)는 보안 검토가 필요해 이번 범위에서 뺐다.

**어떻게:**
- 실측부터 했다. 가상 터미널(pyte)에서 실제 Claude Code 2.1.323·Codex 0.167.1을 띄워 쉬는 중·일하는 중·권한 확인·Esc 뒤·종료 뒤 화면을 찍었다(권한 확인은 모두 Esc로 거절, 파일은 만들어지지 않음). Gemini CLI는 이 기기에 없어 공개 소스의 문구로 화면을 만들었다. 기준 화면은 `src/test/fixtures/agents/`에 있다(경로·세션 id는 가림).
- 입력 기다림 = 화면 맨 아래의 "선택된 번호 항목(`❯`·`›`·`●` + `1.`) + 키 안내(`Esc to cancel`·`enter to confirm`·`(esc)`)". 선택 표시로 어느 에이전트인지 안다.
- 살아 있음: 종료 뒤에도 마지막 상태 줄(`✳ Bloviating…`)과 위 테두리가 화면에 남는다는 것을 실측에서 찾았다. 그래서 일하는 중·쉬는 중은 그 에이전트의 입력란이 맨 아래에 있을 때만 인정한다(Claude는 테두리/❯/테두리 상자, Codex는 `›` 입력 줄 — Codex는 끝날 때 화면을 지운다). #180의 ✻가 종료 뒤에도 남던 빈틈이 함께 메워졌다.
- Terminal은 올라가는 변화(→ 일하는 중·기다림)는 바로, 내려가는 변화(일하는 중 → 쉬는 중 1.5초, 에이전트 → 없음 3초)는 다시 확인한 뒤 버스(`onAgentStatus`)로 알린다. App이 패널별 상태를 모아 탭 표시·알림·목록을 만든다. "끝남"은 보지 않는 사이에 일을 마친 것이고, 그 탭을 보면 지운다.
- 사용량 막대의 회사 이름·색은 에이전트 목록과 같은 값(`AGENT_NAMES`·`AGENT_COLORS`)을 쓰게 합쳤다.
- 왼쪽 패널에 칸이 늘어 메뉴가 바뀌므로 0.22.0으로 낸다. 대기 중인 0.21.12(#186)가 따로 나갈 수 있게 `feat/agent-status` 브랜치에서 작업했다.
- 테스트: `src/agentScan.test.ts`(기준 화면 13장 + 오탐 사례), `src/aiActivity.test.tsx`(실제 Terminal에서 기다림·종료·패널 닫힘), `src/agentPanel.test.tsx`(정렬·이동·빈 화면·칸 표시).
- 실제 앱 확인(격리 테스트 앱, 사용자 자리 비운 때): 실측 화면을 흉내 낸 가짜 Claude로 일하는 중 ✻ → 뒤쪽 탭 `?`·칸의 노란 점·목록 "답을 기다림" → 행 눌러 이동 → 답한 뒤 다른 탭에 있는 동안 끝나면 "끝남"+탭 알림 점 → 보면 "쉬는 중"까지 확인했다.
- 실제 앱에서 찾은 빈틈: 에이전트가 입력 상자를 지우지 못하고 끝나면(비정상 종료 등) 상자 아래에 셸 프롬프트만 찍혀 계속 "쉬는 중"으로 남았다. 셸 통합(OSC 133)이 있는 패널은 명령 끝(D)~다음 시작(C) 사이를 "셸이 프롬프트에 있음"으로 보고 에이전트를 바로 내린다. 통합이 없는 패널(SSH 등)은 화면 판정만 쓴다. 고친 뒤 실제 앱에서 종료 즉시 목록이 비는 것을 확인했다.
- GUI 확인 중 함정: 내가 보낸 HID 입력도 HIDIdleTime을 0으로 만든다. "사용자가 돌아옴" 판정은 내 마지막 동작 뒤에 들어온 입력만 본다.
