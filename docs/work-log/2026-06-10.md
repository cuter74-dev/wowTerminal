## #83 ROOT CAUSE — M5 dup persists in v0.13.11; predictive text is the real culprit (v0.13.12)

GitHub #83 (English) / GitLab #2 (Korean).

### What / Why / How
- The M5 user's screenshot on v0.13.11 still showed `df -h` → `ddf -hdff f -h` at the prompt (command executed correctly). So the v0.13.6 WebGL renderer theory was wrong.
- Re-read the v0.13.5 `wt-ime-diag` traces in GlitchTip — the M5 (isMac) traces had been there all along:
  `nCS:0 nCU:0 nCE:0 | n229:3 | mirrorChars:15 mirrorBs:10 | onDataChars:0` for typing `df -h` (5 keys).
- What this proves:
  1. **M5 fires NO composition events** (`nCS=0`) — the #83 `nativeComposition` bypass never engaged there; the whole "newest WKWebView fires composition events" premise was wrong.
  2. English keystrokes hit **keyCode 229** (3 of them) → the custom IME mirror engaged.
  3. macOS **inline predictive text ("writing suggestions") rewrites the hidden textarea**, so the mirror's prefix-diff sent a backspace+resend storm — 15 chars + 10 backspaces for 5 keystrokes. Net = 5, so the shell line was correct and the command ran; but the churn interleaved with oh-my-zsh's per-keystroke line redraw leaves real stray characters in the xterm buffer. That's why WebGL (full repaint) didn't help — the junk is buffer content, not stale glyphs. And why other terminals are clean — they have no mirror.
- Fix (`Terminal.tsx`): right after `term.open()`, set `term.textarea.setAttribute("writingsuggestions", "false")` — the WebKit attribute that disables inline predictive text (xterm only sets autocorrect/autocapitalize/spellcheck, which don't cover it). With suggestions off, English no longer routes through keyCode 229, the mirror never engages for plain typing, and only real IME composition (Korean etc.) uses it. Also corrected the WebGL comment (kept for GPU accel, but it was not the #83 fix).
- `npm run build` ✅. Needs the M5 user to confirm (the maintainer's machine never reproduced — its trace is `n229:0, onDataChars:5`, pure plain path).

## #88 follow-up — Korean TYPES on Windows now (v0.13.13 confirmed); early line-wrap remains (v0.13.14)

- Windows user screenshot on v0.13.13: **Korean input works** — the composition-view unhide did it. Remaining: the input line wraps after a few characters at inconsistent columns (23, ~50), and cmd's own output wraps at ~65, all far short of the actual terminal width (~165 cols) — classic xterm↔ConPTY size mismatch: cmd wraps at the width ConPTY believes.
- Root cause: a resize race. `spawn` is called with the spawn-time `term.cols/rows`; while the spawn `await` is in flight (ConPTY startup is slow on Windows), the layout-settling refits (rAF/80ms/300ms) resize xterm and fire `onResize` — which drops them (`if (!sessionId) return`). Nothing re-sends the final size after spawn, so ConPTY keeps the stale width forever and cmd wraps its input echo there. Korean (double-width cells) hits the stale edge sooner, which is why it surfaced with Hangul.
- Fix (`Terminal.tsx`): right after the spawn resolves (and `onSession`), send one `resizeCmd` with the current `term.cols/rows` to sync the PTY/remote to the real size. Applies to local PTY and SSH alike. `npm run build` ✅.

## #89 — tmux integration (auto-attach, session picker, tab title sync)

GitHub #89 (English) / GitLab #8 (Korean).

### What / Why / How
- **Auto-attach** (`ssh/types.rs` + `HostForm.tsx` + `App.tsx`): `SshHost.tmux_session: Option<String>` (serde default, old data loads fine). Host form gets a "tmux auto-attach" field (input sanitized to `[A-Za-z0-9_@-]`). On `handleSshConnected`, if the host has a session name, the frontend sends `tmux new-session -A -s '<name>'\r` to the shell — tmux's full-screen redraw wipes the echo, avoiding the fragile hidden-injection approach that caused #34/#37 ghosts.
- **Session picker** (`TmuxPicker.tsx` + Rust): `SshSession.exec_capture()` generalizes the `remote_cwd` exec-channel mechanism (separate channel, 2s timeout, no visible-shell traces); `tmux_sessions()` runs `tmux list-sessions -F '#{session_name}\t#{session_windows}\t#{session_attached}'` and `TmuxSessionInfo::parse_lines` parses it. New commands: `ssh_tmux_sessions(session_id)` and `local_tmux_sessions` (runs via `$SHELL -lc` so Homebrew PATH resolves; Windows returns None). The ⌘K "tmux sessions" entry opens a modal listing sessions (window count + attached badge); picking sends `\x15tmux switch-client -t 'X' 2>/dev/null || tmux attach-session -t 'X'\r` (works inside AND outside tmux); the create row prepends `tmux new-session -d -s 'X' 2>/dev/null;`.
- **Tab title sync** (`commandBus.ts` + `Terminal.tsx` + `App.tsx`): a `titleBus` (`emitTitleChange`/`onTitleChange`); Terminal forwards xterm's `onTitleChange` with its paneId; App maps the leaf to its tab and sets the label (truncated to 32 chars), falling back to `labelForSource` when the title is empty. Covers tmux window titles (`set-titles on`) and regular shell titles.
- `cargo check` ✅, `npm run build` ✅, local production binary running for interactive verification (local tmux session `wt-test` prepared).

## #89 fix + #90 — attach order fix, tmux tab labels, session restore

- **#89 attach order**: the user's first picker test on an SSH host echoed the command and did nothing — `switch-client` (run first) silently switched a client attached *elsewhere* and exited 0, so `attach` never ran. Swapped to attach-first: `tmux attach-session -t X 2>/dev/null || tmux switch-client -t X` — attach succeeds outside tmux, fails (nested) inside where switch-client then switches *our* client. Confirmed working by the user.
- **#89 tab label**: titles only flow if the remote sets them (`set-titles on`), so the tab kept showing the host name. Now attaching via auto-attach or the picker immediately labels the tab `session · host` (`labelTabForLeaf`), with live titles still able to update it later.
- **#90 session restore** (`sessionRestore.ts` + App + Rust): a v1 snapshot (`wowterminal.session.v1` in localStorage) of the main window's tabs — label + pane tree with per-leaf {source, local cwd (OSC 7-tracked), known tmux session} — saved on tab changes and every 15s, restored at startup with fresh leaf ids. Local leaves spawn in their saved cwd (`pty_spawn` gained `cwd: Option<String>`, applied via `CommandBuilder::cwd` only if the dir still exists); SSH leaves reconnect; leaves with a known tmux session re-attach in `onSession` (input is buffered, safe before the shell prompt). Host-config auto-attach defers to a pending restore attach to avoid double commands. Detached windows keep the registry handover flow untouched.
- `cargo check` ✅, `npm run build` ✅, smoke-tested: quit → relaunch restores and boots cleanly.
