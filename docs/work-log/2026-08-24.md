## #149 — 모바일 스크롤바 상시 표시

**보고**: "태블릿(Android)에서 파일탐색기가 스크롤이 안돼" + "모바일에서도 스크롤이면 스크롤바를 보이게 해줘".

**재현/진단** (에뮬레이터 직접 구동):
- Android 에뮬레이터(Pixel Tablet, API 36) 신규 구축 → dev 빌드 설치 → 파일 브라우저에 80개 파일 → CDP 합성 터치·`adb input swipe` 모두에서 **스크롤 자체는 정상 동작** 확인.
- 단 Android WebView는 내부 overflow 요소의 오버레이 스크롤바를 그리지 않음(Chromium #40226034) — 스크롤 가능 여부가 보이지 않고 잡을 수도 없어 "스크롤이 안 된다"로 인지됨.

**수정**:
- `main.tsx`: 모바일(iOS/Android)이면 `body.plat-mobile` 클래스 부여.
- `App.css`: `body.plat-mobile ::-webkit-scrollbar` 8px 반투명 라운드 썸 상시 표시(커스텀 웹킷 스크롤바는 WebView에서도 그려짐). 데스크탑 외관 불변.

**검증**: 에뮬레이터에서 dev 빌드 재설치 → 파일 브라우저 로컬 패널에 세로 스크롤바 썸 표시 확인, 스와이프 시 리스트/썸 동시 이동 확인. `tsc --noEmit`·`vite build` 통과.

## #150 — iOS 세로 터치 스크롤 불능 (별도 이슈, 추적 중)

- iPad 시뮬레이터(iOS 26.5)에서 **앱 내 모든 세로 터치 스크롤 불능** 재현(파일 목록·호스트 목록·React 밖 순수 overflow div까지). 가로(하단 키바)는 정상. 탭은 정상.
- 디버그 오버레이 계측: 탭은 touchstart가 DOM에 도달하지만 **세로 팬은 이벤트가 아예 도달하지 않음** → 네이티브 레이어가 소비.
- 기각된 가설: -webkit-overflow-scrolling, fixed→absolute, overscroll-behavior 제거, 페이지 스크롤 허용, wry `setBounces(false)`(패치 wry로 재빌드해도 동일).
- **결정적 대조**: 같은 최소 페이지를 같은 시뮬레이터의 Safari로 열면 동일한 부드러운 합성 팬(cliclick 다단계 드래그)으로 정상 스크롤 → 페이지·제스처는 무죄, Tauri 임베드 WKWebView만 이상. 주의: 순간이동식 합성 드래그는 iOS에선 Safari에서도 팬으로 인식 안 됨(테스트 함정).
- 다음: tao/wry 뷰 계층·제스처 인식기 상호작용 조사, 최소 Tauri iOS 앱 재현 → 업스트림 보고 판단, 실기기 확인.
