## #189 — 원격(SSH·tmux)에서도 에이전트 표시, 에이전트 표준 신호 (GitLab #88)

**무엇:** 원격 서버의 tmux 안에서 돌리는 에이전트도 표시되게 하고, 에이전트가 보내는 표준 신호를 받는다.

**왜:** 사용자 질문("원격 서버는 표시를 못 하나?")과 기능 선택(11-14 "1,2,3,7"). 실제 앱 + Ubuntu 컨테이너로 재현했다. 서버 언어가 UTF-8이면 SSH·tmux 안에서도 `?`·목록이 잘 뜬다. `LC_ALL=C`이면 tmux가 `❯`·회전 표시·`…`를 `_`로 바꿔 아무것도 잡히지 않는다. 맥의 ssh 명령은 `LANG`을 넘기는데(SendEnv) wowTerminal SSH는 넘기지 않아, 기본 언어가 없는 서버에서는 wowTerminal로 연 tmux만 깨진다.

**어떻게:**
- `src-tauri/src/locale.rs`: SSH는 앱에 UTF-8 `LANG`이 있으면 그 값을, 없으면(Finder 실행) `LC_CTYPE=C.UTF-8`을 셸 채널에 요청한다. `ko_KR.UTF-8`은 그 로캘이 없는 서버에서 setlocale 경고를 띄우므로 문자 집합만 정한다. 로컬 PTY는 `LANG`이 비어 있으면 시스템 언어(예: `ko_KR.UTF-8`)로 채운다(macOS 터미널 앱과 같음).
- `src/agentSignals.ts`: 설치된 Claude Code 2.1.325에서 확인한 OSC 7501 형식(`state=working|blocked|done|idle|error|clear:app=claude-code[:kind][:progress]`)과 질의(`OSC 7501 ; ?`)를 해석한다. Terminal이 질의에 답하고, 보고가 오는 동안은 화면 판정 대신 보고를 쓴다(하위 작업 `id=` 보고는 제외). tmux 안에서는 Claude Code가 tmux에게 물어 보내지 않으므로 화면 판정이 계속 쓰인다.
- OSC 9(글)·777(`notify;제목;본문`)·99(kitty, 조각 모음) 알림 → 보고 있지 않은 탭이면 알림 점 + 데스크톱 알림(방금 같은 패널의 에이전트 알림을 보냈으면 건너뜀). 벨 → 알림 점. OSC 9;4·7501 진행률 → 에이전트 목록 행에 `%`.
- 테스트: `locale.rs` 3개, `agentSignals.test.ts` 10개, `aiActivity.test.tsx`에 실제 Terminal 수준 5개(질의 응답, 보고 우선·clear, 하위 작업 무시, 진행률, 알림·벨).

## #190 — 에이전트 탭 Shift+Enter 줄바꿈, ⌥를 Meta로 (GitLab #89)

**무엇·왜:** xterm.js 6에는 kitty 키보드 규약이 없어 Shift+Enter가 그냥 Enter(`\r`)로 가고, Claude Code·Codex에서 바로 전송된다. Claude Code 공식 문서는 어느 터미널에서나 Ctrl+J를 줄바꿈으로 받는다고 한다(Codex·Gemini도 같음).

**어떻게:**
- 에이전트가 감지된 창(#187의 `agentNow`)에서만 Shift+Enter를 Ctrl+J(`\n`)로 바꿔 보낸다. 한글 조합 중(keyCode 229·isComposing)에는 건드리지 않는다. 평범한 셸은 그대로 `\r`.
- 설정 → 터미널 "⌥ 키를 Meta로 사용"(macOS에서만 보임, 기본 꺼짐): xterm `macOptionIsMeta`. Claude Code의 ⌥+Enter 줄바꿈·⌥+P 같은 단축키가 동작한다. 켜면 ⌥로 특수문자를 칠 수 없다.
- 테스트: `src/agentKeys.test.tsx`(에이전트 창 → `\n`, 평범한 셸 → `\r`, 조합 중 무시). ⌥ 동작은 xterm이 Node 환경을 늘 맥이 아닌 것으로 봐서 재현이 안 돼 실제 macOS 앱에서 확인한다.

## #191 — 호스트별 접속 후 시작 명령, SSH 에이전트 포워딩 (GitLab #90)

**무엇:** 호스트 편집 창에 두 칸을 더했다.
- **접속 후 시작 명령**(예 `cd ~/proj && claude`): 새로 연 세션에서 한 번 입력한다. tmux를 쓰는 호스트는 tmux 세션이 새로 생길 때만 그 안의 셸에 입력한다(`tmux has-session … || { new-session -d … && send-keys -l … && send-keys Enter; }; attach`). 이미 있던 세션(돌고 있는 Claude Code 등)에는 아무것도 입력하지 않는다. 복원된 탭·끊긴 뒤 재접속에도 다시 보내지 않는다.
- **SSH 에이전트 포워딩**(`ssh -A`, 기본 꺼짐): 셸 채널에서 `auth-agent-req@openssh.com`을 보내고, 서버가 여는 에이전트 채널을 로컬 ssh-agent(SSH_AUTH_SOCK)에 잇는다. 경고 문구: 접속 중에는 그 서버 관리자도 내 에이전트를 쓸 수 있다.

**왜:** 사용자 기능 선택(11-14 "1,2,3,7"의 7번).

**어떻게:**
- tmux 문법은 이 Mac의 tmux 3.7(별도 소켓)로 실제로 확인했다: 새 세션일 때만 실행, 다시 부르면 보내지 않음, `=이름` 정확 일치.
- 에이전트 포워딩은 연결마다 "허용" 표시(AtomicBool)를 두고, 사용자가 켠 호스트의 셸 연결에서만 켠 뒤 요청한다. 요청하지 않은 연결에서 서버가 에이전트 채널을 열면 그대로 닫는다(악성 서버가 몰래 내 에이전트를 쓰지 못하게). SFTP·터널 연결은 늘 꺼져 있다.
- 세션 데몬 프로토콜: `SshConnect`에 `#[serde(default)] agent_forward`를 덧붙였다(append-only). 예전 UI의 요청도 새 데몬이 읽는다(테스트). 예전 데몬은 이 값을 모르고 포워딩만 빠진다.
- hosts.toml: `startup_command`·`agent_forwarding` 모두 기본값이 있어 예전 파일도 그대로 읽힌다.
- 테스트: `src/hostStartup.test.ts`(5개), `daemon::proto` 호환 1개. 실제 포워딩은 데모 서버에서 확인 예정.

## #192 — SSH 탭에 이미지 붙여넣기 (GitLab #91)

**무엇:** SSH 탭에 클립보드의 이미지(글 없이 이미지만)를 붙여넣으면 서버의 사용자별 임시 폴더(`/tmp/wowterminal-paste-<uid>`, umask 077)에 올리고 그 경로를 붙여넣는다. 서버의 Claude Code에 화면 캡처를 줄 때 쓴다. 10MB까지.

**왜:** 사용자 기능 선택(11-14 "1,2,3,7"의 2번). 지금은 SSH 탭에서 이미지를 붙여넣으면 아무 일도 없다.

**어떻게:**
- SFTP 대신 **세션과 같은 연결**에 exec 채널을 열어 stdin으로 바이트를 보낸다(`umask 077; mkdir -p … && cat > …`). SFTP는 비밀번호를 그때그때 입력하는 호스트를 지원하지 않는데, 이 방식은 인증 방식·점프 호스트와 상관없이 터미널과 같은 서버·사용자로 올라간다.
- 세션 데몬 프로토콜 4: `SshUploadBytes`를 덧붙였다(append-only). UI는 데몬이 4 미만이면 보내지 않고 SFTP로 올린다(저장된 인증이 있는 호스트만, `/tmp/wowterminal-paste-<사용자>` 0700). 데몬 프레임 16MiB에 base64가 들어가도록 10MB 상한.
- ⌘V는 paste 이벤트를 캡처 단계에서 받아 xterm보다 먼저 처리한다. 글이 함께 있으면 글 붙여넣기 그대로. Windows·Linux의 Ctrl+V와 우클릭 붙여넣기는 글이 비어 있을 때 `navigator.clipboard.read()`로 이미지를 찾는다. 진행·성공·실패는 토스트(11개 언어).
- 테스트: `src/pasteImage.test.tsx`(이미지 → 업로드·경로 붙여넣기, jpeg 확장자, 글이 있으면 그대로, 로컬 탭 무시). 데몬 프로토콜 버전 테스트를 4로.

## 실제 앱 확인 (#189~#192)과 고친 것

격리 테스트 앱(깨끗한 환경, 사용자 자리 비움) + 기본 언어를 지운 Ubuntu 컨테이너로 확인했다.
- #190: 에이전트 창에서 Shift+Enter → `\n`, Enter → `\r`, ⌥+P(꺼짐) → `π`. 설정에서 "⌥를 Meta로"를 켜면 ⌥+P → `\x1bp`, ⌥+Enter → `\x1b\r`.
- #191: 호스트 시작 명령이 tmux 새 세션 `w` 안에서 실행됐다. 에이전트 포워딩: 원격 `ssh-add -l` → "The agent has no identities."(rc=1, 로컬 에이전트에 연결됨 — 안 되면 rc=2).
- #189: 서버에 `LANG`이 없어도 `LC_CTYPE=C.UTF-8`이 넘어가 tmux가 글자를 깨뜨리지 않았고, 탭 `?`·목록 "답을 기다림"이 떴다. 실제 Claude Code 2.1.325 디버그 기록에 `programStatus=yes (probe: OSC 7501 reply)` — 앱이 질의에 답했고, 탭 제목에서 Claude의 `✳`가 빠졌다(지원 터미널에서만 그렇게 한다).
- #192: SSH 탭에서 ⌘V로 PNG를 붙이자 `/tmp/wowterminal-paste-1001/paste-….png`(폴더 700, 파일 600, 원본과 같은 1796바이트)로 올라가고 경로가 붙여넣어졌다.

확인 중 고친 것:
- 설정의 "업데이트 확인" 버튼이 실제로는 확인하지 않고 늘 "최신 버전입니다" 경고창을 띄우고 있었다. 이제 공용 업데이트 상태(#188)로 확인하고 결과(새 버전·최신·실패)를 버튼 옆 글로 보인다. 새 버전이면 "나중에"로 숨긴 안내 줄도 다시 띄운다. 모바일(스토어 업데이트)에서는 숨긴다.
- 에이전트 목록 행: 탭 이름에 서버 이름이 이미 있으면(tmux 탭 "w · demo-server") 다시 붙이지 않는다.
- 테스트 도구 함정: HID로 보낸 ⌥ 키가 시스템에 눌린 채 남아(⌥+클릭이 xterm 커서 이동 `\x1b[C`로 감) 바로 풀었다 — 사용자 키보드에도 영향이 갈 수 있어 수정 키를 쓴 뒤엔 항상 놓는다.
