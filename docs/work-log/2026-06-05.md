## #80 — Local shell missing PATH (non-login shell skips ~/.zprofile)

### What / Why / How
- Symptom: the user's screen shows .zshrc:116/130 command not found: pyenv/jenv + commands not working. v0.10.0.
- Cause: pty/manager.rs spawns the shell non-login. macOS Terminal.app uses a login shell → reads /etc/zprofile (path_helper) and ~/.zprofile. Homebrew's official install puts brew shellenv in ~/.zprofile, so a non-login shell drops the entire PATH for Homebrew and tools installed via it → command not found.
- Verification: `/bin/zsh -c 'echo $PATH'` (non-login) vs `/bin/zsh -l -c ...` (login) — only login reflects /etc/zprofile path_helper. Confirmed path_helper in /etc/zprofile.
- Fix: zsh `cmd.arg("-l")`. The temp .zprofile we already created (sourcing the user's .zprofile) was dead under non-login, and `-l` makes it actually load. For bash, a login shell ignores --rcfile, so keep it non-login but source /etc/profile + ~/.bash_profile/.bash_login/.profile in the rcfile to secure PATH.
- pty tests: 4 pass.
