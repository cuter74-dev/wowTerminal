## #153 — 세션 데몬 Phase 1 (업데이트/재시작에도 로컬 세션 지속)

**문제**: 로컬 셸이 앱의 자식 프로세스라, 자동 업데이트의 `relaunch()`로 앱이 재시작되면 실행 중이던 Claude Code/Gemini가 함께 죽었다. 세션 복원(#90)은 레이아웃만 저장해 **새 세션을 다시 스폰**할 뿐이었다.

**원인(정확히)**: 부모-자식 관계가 아니라 **앱이 죽으며 PTY master fd가 닫혀 셸에 SIGHUP**이 가는 것. 따라서 master fd를 UI보다 오래 사는 프로세스가 들고 있으면 해결된다. (실측 스파이크: detached 자식은 부모 종료 후 PID 1로 재부모화되어 생존.)

**설계**: 기존 sink seam을 그대로 활용 — 매니저는 `DataSink`/`ClosedSink`가 무엇을 하는지 모르므로, sink를 "소켓 이벤트 발행"으로 바꾸면 `PtyManager`를 **데몬에서 그대로 재사용**할 수 있다.
- `src-tauri/src/daemon/`: `proto.rs`(4바이트 LE 길이 + JSON 프레임, 요청/응답 id 매칭 + 서버 푸시 이벤트 멀티플렉스), `server.rs`(데몬 루프, PtyManager host, 유휴 종료), `client.rs`(UI 측 클라이언트, detached 스폰).
- 데몬은 별도 바이너리가 아니라 **같은 실행 파일의 `--daemon --socket <path>` 모드**(`main.rs`) — 매니저·스토어를 그대로 host.
- detached 스폰에 `setsid`(libc) 사용 — 앱 세션/프로세스 그룹에서 분리해야 relaunch로 함께 죽지 않는다.
- `PtyState { manager, daemon }`: 데몬이 있으면 pty 커맨드를 위임, 없으면 기존 인프로세스 경로(**무회귀 폴백**). 커맨드 시그니처·이벤트 이름(`pty:output`/`session:closed`)은 불변이라 프론트 계약 그대로.
- 프로토콜은 **append-only**(미지 필드 무시) — 업데이트 후 구버전 데몬에 새 UI가 붙는 게 이 기능의 핵심이라 기존 메시지 의미를 바꾸면 안 된다.

**재attach(경합 없는 방식)**: spawn 요청에 `attach` 힌트를 넣어, 그 세션이 데몬에 아직 살아있으면 스폰하지 않고 그 id를 그대로 반환한다. 프론트는 반환 id가 힌트와 같으면 "재attach됨"으로 보고 `session_history`를 재생한다. (프론트에서 미리 생존 조회 후 렌더를 막는 방식의 렌더 경합을 피함.)
- `sessionRestore.ts`: `SavedPane.sid` + `LeafProbe.getSessionId` + `RestoredSession.initAttach` 추가 — 세션 id를 스냅샷에 남긴다(데몬 도입으로 "프로세스는 어차피 죽는다"는 전제가 깨졌으므로).
- `App.tsx` → `PaneView` → `Terminal`로 `restoreSessionId` 전달.

**kill 의미 분리**: pane/탭을 사용자가 닫으면 kill(종전과 동일), **앱 종료/업데이트 재시작이면 kill 금지**(세션을 데몬에 남긴다). `terminalRegistry`에 `markAppTeardown/isAppTeardown`을 두고 `main.tsx`의 `beforeunload`와 `HostList.applyUpdate`(relaunch 직전)에서 표시한다.

**부수 수정**: `ssh/session.rs`의 기존 깨진 테스트(`SshSession::connect` 시그니처 드리프트 — `ClosedSink` 인자 누락)를 고쳤다. 이게 lib 테스트 바이너리 전체를 막고 있어 신규 테스트도 못 돌리는 상태였다. `PtyManager::list_sessions()` 추가.

**검증**:
- `cargo test --lib` 49개 전부 통과(기존 깨진 테스트 복구 + proto 신규 4개: 프레임 라운드트립, EOF, envelope flatten, **미지 필드 무시**).
- `tsc --noEmit` 통과.
- **프로토콜 e2e 실측**(실제 데몬 바이너리 + 소켓 클라이언트): 세션 스폰 → 마커 출력 확인 → **클라이언트 연결 끊음(UI 재시작 모사)** → 재연결 시 `list_sessions`에 세션 생존 → `session_history`에 스크롤백 보존 → 재attach 후 입출력 정상 → 명시적 `pty_kill`은 여전히 세션 종료. 전부 PASS.
- **실제 앱 e2e 검증 완료**(클린 로컬 사본 `/private/tmp/wtdaemon`에서 `tauri dev` 구동 — 원본 작업폴더는 Synology 마운트의 node_modules 읽기 타임아웃으로 실행 불가):
  1. 앱이 데몬을 자동 스폰(`--daemon --socket ~/Library/Application Support/wowterminal/daemon.sock`), 세션 4개 보유.
  2. 한 세션에 마커 + 장수 루프 주입 후 **UI 프로세스를 강제 종료**(업데이트 relaunch 모사).
  3. → 데몬 생존, **세션 4개 전부 생존**, 스크롤백 보존, 해당 세션이 여전히 상호작용 가능(Ctrl-C + echo 왕복 확인).
  4. 앱 재시작 → **동일한 세션 id 4개에 재attach, 신규 스폰 0개**(중복 세션 없음). 재attach 경로가 실제로 동작함을 확인.
- 검증 후 dev 앱·테스트 데몬은 정리했고, 사용자가 쓰는 설치본(/Applications/wowTerminal.app)은 건드리지 않았다.
