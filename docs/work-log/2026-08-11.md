## #144 — Android 상단 메뉴가 시스템 상태바와 겹침 (edge-to-edge 인셋)

### What / Why
- 제보: Android 태블릿에서 앱 상단 메뉴가 상태바 밑에 깔려 안 보임.
- 원인: tauri 생성 `MainActivity`가 `enableEdgeToEdge()` 호출(+Android 15/targetSdk 35+는 강제)로 웹뷰가 시스템 바 아래까지 확장되는데 인셋 패딩이 어디에도 없었다. Android WebView는 CSS `env(safe-area-inset-*)`를 신뢰성 있게 제공하지 않아 웹 측 해결이 불가.

### How
- `MainActivity.kt`: `ViewCompat.setOnApplyWindowInsetsListener`로 콘텐츠 루트에 시스템 바+디스플레이 컷아웃 인셋 패딩 — 상단 상태바·하단 내비바 겹침 동시 해결.
- `themes.xml`(+night): `windowBackground`를 타이틀바 색(#1F1F23)으로 — 상태바 뒤 배경이 앱과 이어짐.
- 후속 발견(adb 스크린샷 실측): 겹침이 풀리자 **탭 0개일 때의 빈 탭바 띠**가 드러남 — 모바일은 + 버튼이 없어(로컬 셸 없음) 빈 줄만 남는 구조. `TabBar.tsx`에서 모바일+탭 0개면 탭바를 숨김.
- 검증: 수정 APK를 태블릿에 설치하고 **adb 스크린샷으로 전/후 비교 실측** — 겹침 제거, 빈 띠 제거 확인.

### gen/android를 git 추적으로 전환
- 루트 `.gitignore`가 `src-tauri/gen/` 전체를 무시해 이 커스텀(인셋 처리·서명 설정)이 재생성 시 날아가는 구조였다. android만 추적하도록 세분화(apple/schemas는 계속 무시), 빌드 산출물·`keystore.properties`(로컬 비밀)·`tauri.properties`·jniLibs/assets 제외. 40개 파일 커밋.

### 후속 — 앱 아이콘이 기본 Tauri 아이콘으로 바뀌어 있던 문제
- `tauri android init` 재생성이 res/mipmap을 **기본 Tauri 아이콘으로 교체**했는데 그대로 빌드·설치·커밋까지 나갔다(제보로 발견). iOS 워크플로에는 `tauri icon` 재생성 스텝이 있었지만 Android 로컬 빌드 절차에는 없었다.
- repo에 보존된 정식 아이콘(`src-tauri/icons/android/` — mipmap 5종 + adaptive xml + background color)을 gen/android res로 복원하고, 기본 템플릿의 벡터 아이콘 잔재(drawable/drawable-v24)를 제거. APK에서 아이콘을 추출해 정식 로고 확인.

### 후속 2 — 접속 시 앱 전체가 죽던 회귀 (내 실수) + 에러 화면 가독성
- 탭바 숨김 수정을 **훅 두 개 사이에 early return으로** 넣어 훅 규칙 위반 — 모바일에서 탭 0→1(접속) 순간 훅 개수 불일치로 React 크래시, ErrorBoundary로 전락. 스크린샷까지 확인했지만 접속 시나리오를 안 밟은 검증 구멍. return을 모든 훅 뒤로 이동 + 경고 주석.
- 그 과정에서 드러난 것: ErrorBoundary fallback이 무스타일 `<p>`라 검정 화면에 묻혀 "너무 어두워 안 보임" — 밝은 안내 + Reload 버튼이 있는 화면으로 교체.

### 후속 3 — AI 패널: 긴 모델명이 우측 버튼들을 화면 밖으로 밀던 문제
- 태블릿 실측(adb 캡처): 헤더가 한 줄 고정이라 백엔드 표시명이 길면 🧠/⚙️/🕘/＋가 잘림. `flexWrap: wrap` + 셀렉트 `minWidth:0` — 좁으면 두 줄, 넓으면 종전대로 한 줄. 수정 후 캡처로 버튼 전부 표시 확인.

## #146 — Android: 시크릿(API 키·SSH 비번)이 조용히 증발하던 문제

### What / Why
- 제보: 데스크탑에선 되는 Ollama Cloud 키가 태블릿에선 401. 데스크탑 쪽은 실측으로 키 자체 문제(재발급으로 해결)였지만, Android는 별개 원인.
- **keyring 크레이트(3.6.3)에 Android 백엔드가 없다**(macos/ios/windows/secret-service/keyutils/mock뿐). 미지원 플랫폼은 인메모리 mock으로 폴백 — save가 성공하는 척만 하고 영속 안 됨. API 키·SSH 비번·패스프레이즈 전부 해당. #142에 이은 Android 저장 구멍 2호.

### How (`lib.rs`)
- 시크릿 저장을 3분기: 데스크탑(머신키 EncryptedFileStore, 불변) / iOS(KeyringStore=키체인, 불변) / **Android: EncryptedFileStore + 설치별 랜덤 키 파일**(`secret.key`, 첫 실행 생성) 패스프레이즈.
- machine-uid도 Android 미지원이라 랜덤 키 파일 방식 — 키 파일이 같은 앱 내부 저장소에 있으므로 보호 경계는 앱 샌드박스 자체(root 없는 기기에서 타 앱 접근 불가). 데스크탑 머신키 방식과 동등한 트레이드오프로 코드에 명시.

### 검증
- 태블릿 실기기: 키 재입력·저장 → 대화 성공(사용자 확인 "이제 잘 되네") + `run-as`로 `/data/data/.../secret.key`(64B)·`secrets.enc`(213B) 생성 실측 — 이전엔 아무 파일도 안 생겼다.
- 데스크탑 `cargo check` 통과(분기 불변).
