## #83 follow-up — M5 stray chars persist past writingsuggestions; rewrite-storm suppression (v0.14.2)

GitHub #83 (English) / GitLab #2 (Korean).

- The M5 user reports the `ddf` bug persists on builds with `writingsuggestions="false"` (v0.13.12+). So the attribute doesn't stop whatever routes English typing through keyCode 229 + textarea rewrites on that machine (third-party IME? newer-macOS behavior the attribute doesn't govern?).
- New approach — fix the damage instead of the trigger: the visible corruption always comes from the mirror's multi-backspace rewrite storms (v0.13.5 trace: 15 chars + 10 backspaces for 5 keys). `flushMirror` now refuses rewrites that erase 2+ chars of **pure-ASCII** content: a terminal wants raw keystrokes, so OS-driven rewrites are ignored (tracking resyncs; subsequent appends flow normally). Appends, single backspaces (real Backspace key), and any value containing CJK (genuine composition rewinds) behave exactly as before, so old-WKWebView Korean is untouched.
- Re-added the lightweight macOS-only counters diag (`wt-ime-diag2`: n229/nCS/onDataChars/mirrorBs/mirrorChars/**bsSuppressed** + the writingsuggestions attribute value), sent on 3s input idle, ≤4 sends/session — verifies on the M5 whether 229 still fires and whether suppression is doing the work.

## #93 — log-driven fix: Windows confirm dialogs blocked by ACL

GitHub #93 (English) / GitLab #12 (Korean). Found by reading GlitchTip (issue 11, Windows v0.14.1), not a user report: `Command plugin:dialog|confirm not allowed by ACL`. On WebView2 `window.confirm` routes through the dialog plugin; the capability only granted default/save/open, so all delete confirmations silently failed on Windows. Added `dialog:allow-confirm/ask/message` to `capabilities/default.json`. Also in the logs: a Linux GTK init panic (issue 12, AppImage on a machine where GTK failed to initialize) — tracked, not yet actionable without more context; and the maintainer's clean wt-ime-diag2 baseline (n229=0). No M5 traces exist after v0.13.5 — diag was removed in v0.13.6 and v0.14.2 (which re-adds it) is still in CI, so the M5 "still broken" report was against ≤0.14.1 (writingsuggestions only, no suppression).
