GitHub #95 (English) / GitLab #14 (Korean). The maintainer made Korean/English input the top verification priority ("입력 부분은 항상 체크해"). External keystroke automation (System Events) failed on this multi-display/Spaces setup (keys never reached the app; screencapture also unreliable on the virtual displays), so the app got a built-in harness:

- `src/inputSelfTest.ts`: launching with one-shot localStorage `wowterminal.selftest`="1" skips session restore (isolation — synthetic input can only hit a fresh local tab; this guard matters: an earlier external attempt typed into a restored remote tmux session) and drives the hidden xterm textarea with synthetic events through the real paths — bulk insertText for plain typing (per-char keydown synthesis stalled nondeterministically), Backspace keydowns, and the macOS IME mirror via keyCode-229 keydown + textarea value transitions (growth = composition, shrink = deletion).
- Verification is external: the shell writes /tmp/wt-st*.txt, asserted byte-exact; progress trace + 0.5s heartbeat go to localStorage (read via the WKWebView sqlite) to distinguish driver stalls from context death.
- First full pass: T1 `st-en-abcxyz` ✅ (typing+BS), T2 `안녕` ✅ (mirror composition), T3 `가나` ✅ (composition+deletion) — keys→xterm→PTY→shell→execution verified end-to-end on the maintainer's Mac.
- User's session snapshot was backed up before testing and restored after; the app is back up with their tabs.
