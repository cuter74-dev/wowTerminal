## #29 — Streaming LLM responses

- Backend: added `complete_stream(req, on_delta: DeltaSink)` to the `AiBackend` trait (the default impl is a non-stream fallback that runs `complete` and delivers it whole). The OpenAI-compatible adapter requests with `stream: true` → parses `bytes_stream()` SSE (`data:` chunks) → `on_delta` per delta, returns the full accumulation on completion.
- `ai_complete_stream` command: sends `delta`/`done`/`error` via a Tauri `Channel<StreamEvent>`. Goes through `registry.complete_stream`.
- Frontend (AIPanel): `new Channel()` + `onmessage` accumulates tokens into the last assistant message. On `done`, save the full message to the conversation history. `ai_complete` (non-stream) is kept for compatibility.

## Remove Keychain prompt — machine-key-based encrypted store

- Problem: as an unsigned build, the macOS Keychain asks for a password on every app run/access (an unsigned binary doesn't keep "always allow"; in dev it changes every recompile).
- Solution: switch the secret store from the OS keyring (`KeyringStore`) to `EncryptedFileStore` (AES-256-GCM, `~/Library/Application Support/wowterminal/secrets.enc`). The encryption key is derived from `machine-uid` (`machine_passphrase()`) → no prompt. ssh/ai share the same store.
- Trade-off: one level lower security than the OS keyring (decryptable on the same machine·user) — chosen for personal dev/use.
- Migration: existing Keychain-stored items aren't auto-migrated to the new file → SSH passwords/LLM API keys must be re-entered once. Fixed `resolve_auth`'s `Password{secret_id}` to **fall back to a password-input modal** instead of erroring when the secret isn't found (so existing hosts connect after the store switch).

## Korean (CJK) IME input fix — WKWebView

- Symptom: when typing Korean in the terminal, consonants·vowels go out separately (`ㄴ나는`) or the first jamo remains, and Enter produces a double newline.
- Diagnosis (console logs): WKWebView (macOS) does **not** send `compositionstart/end` events to this textarea and only gives keyCode 229 for composition keys. So xterm's composition handler can't catch syllable boundaries and leaks broken jamo/syllables via onData. However, the `input` event and `textarea.value` always hold the correct full text (`insertText`=committed, `insertReplacementText`=composing).
- Solution (`Terminal.tsx`):
  - Composition keys (keyCode 229) are blocked from xterm processing by `return false` in `customKeyEventHandler` → enter `imeActive`. Once Korean starts, the whole line (including spaces·English) is handled via the textarea **mirror**, ending on Enter/arrow/Ctrl, etc.
  - Mirror: in the `input` event (capture phase, `stopImmediatePropagation` to block xterm double-processing), reflect `textarea.value` to the PTY — erase past the common prefix with backspaces (`\x7f`) and send the new tail.
  - **Serialize** `writeToSession` as a promise chain — fixes a problem where the order reversed (race) when sending `"ㄱ"`+`"\x7f가"` consecutively, leaving a jamo behind.
  - Ignore IME-time output in onData + treat standalone compatibility jamo (U+3130–U+318F) as a leak and drop them (removes the first-jamo leak).
  - Enter doesn't send `\r` directly; after ending the mirror it delegates to xterm → a single `\r` (fixes the double newline).

## File browser start location = terminal cwd (remote)

- Inject a hook so the shell emits OSC 7 (`\e]7;file://$PWD\a`) on directory change, and the terminal catches it via `term.parser.registerOscHandler(7)` to track cwd (`TerminalHandle.getCwd`). When opening the file browser, use the cwd of the focused (SSH) panel as the remote start path.
- **Remote (SSH)**: can't control the remote rc → inject the OSC 7 hook at runtime after connect. To preserve banner/MOTD, save the cursor position just before injection (ESC 7) → restore at the end of setup (ESC 8) + erase-below (ESC[J) to remove only the echoed setup lines.
- **Local**: the file browser only opens on SSH so the local cwd isn't used, so no OSC 7 injection (the attempted rc/clear approach was all removed due to cosmetic issues).
- **Local zsh `%` indicator**: not something we made — it's zsh's default PROMPT_SP behavior (a marker for a line without a newline). It shows up at the first PTY prompt with no login message → removed by launching local zsh with `+o promptsp` (non-intrusive to rc/env).

## #31 — Preserve scrollback (prior output) on session handover

- Backend: a per-session output ring buffer `HistoryStore` (512KB cap, drops the front when exceeded). pty/ssh share the same store (the session id is a unique UUID). Wraps the sink in build_manager/build_state to accumulate while emitting. On an actual kill, removes that session's history (kept on handover).
- Command `session_history(sessionId)` → accumulated output base64.
- Frontend (attach mode): instead of a screen snapshot, fetch history and replay with `term.write` → restore scrollback from before the detach too. Snapshot fallback on failure/empty.
- Note: the "only the first tab opens in a new window" symptom right after detach was a transient state where the buffer was empty because the session was created before the history feature was applied (dev restart). After restart, new sessions accumulate from the start and work fine.
