## #29 — 스트리밍 LLM 응답

- 백엔드: `AiBackend` trait에 `complete_stream(req, on_delta: DeltaSink)` 추가(기본 구현은 `complete` 후 통째 전달하는 non-stream 폴백). OpenAI 호환 adapter가 `stream: true`로 요청 → `bytes_stream()` SSE(`data:` 청크) 파싱 → delta마다 `on_delta`, 완료 시 누적 전체 반환.
- `ai_complete_stream` 명령: Tauri `Channel<StreamEvent>`로 `delta`/`done`/`error` 전송. `registry.complete_stream` 경유.
- 프론트(AIPanel): `new Channel()` + `onmessage`로 마지막 assistant 메시지에 토큰 누적 표시. `done`에서 전체 메시지로 대화 이력 저장. `ai_complete`(non-stream)는 호환용으로 유지.

## Keychain 프롬프트 제거 — 머신 키 기반 암호화 저장소

- 문제: unsigned 빌드라 macOS Keychain이 앱 실행/접근 때마다 비밀번호를 물음(서명 안 된 바이너리는 "항상 허용"이 유지 안 됨, dev는 재컴파일로 매번 변함).
- 해결: secret 저장소를 OS 키링(`KeyringStore`) → `EncryptedFileStore`(AES-256-GCM, `~/Library/Application Support/wowterminal/secrets.enc`)로 전환. 암호화 키는 `machine-uid`에서 파생(`machine_passphrase()`) → 무프롬프트. ssh/ai가 같은 store 공유.
- trade-off: OS 키링보다 한 단계 낮은 보안(같은 머신·사용자면 복호화 가능) — 개인 개발/사용 용도 선택.
- 마이그레이션: 기존 Keychain 저장분은 새 파일로 자동 이전 안 됨 → SSH 비번/LLM API 키 1회 재입력 필요. `resolve_auth`의 `Password{secret_id}`가 secret 미발견 시 에러 대신 **비밀번호 입력 모달로 폴백**하도록 수정(저장소 전환 후 기존 호스트 접속 가능).

## 한글(CJK) IME 입력 수정 — WKWebView

- 증상: 터미널에 한글 입력 시 자음·모음이 따로 나가거나(`ㄴ나는`) 첫 자모가 남고, Enter 시 줄바꿈이 두 번.
- 진단(콘솔 로그): WKWebView(macOS)는 이 textarea에 `compositionstart/end` 이벤트를 **안 보내고** 조합 키에 keyCode 229만 준다. 그래서 xterm의 조합 처리기가 음절 경계를 못 잡고 깨진 자모/음절을 onData로 흘림. 단, `input` 이벤트와 `textarea.value`는 항상 올바른 전체 텍스트를 담음(`insertText`=확정, `insertReplacementText`=조합 중).
- 해결(`Terminal.tsx`):
  - 조합 키(keyCode 229)는 `customKeyEventHandler`에서 `return false`로 xterm 처리 차단 → `imeActive` 진입. 한글이 시작되면 그 줄 전체(공백·영어 포함)를 textarea **미러**로 처리하고, Enter/화살표/Ctrl 등에서 종료.
  - 미러: `input` 이벤트(캡처 단계, `stopImmediatePropagation`으로 xterm 이중 처리 차단)에서 `textarea.value`를 PTY에 반영 — 공통 접두 이후를 백스페이스(`\x7f`)로 지우고 새 꼬리 전송.
  - `writeToSession`을 프로미스 체인으로 **직렬화** — `"ㄱ"`+`"\x7f가"` 연속 전송 시 도착 순서 역전(race)으로 자모가 남던 문제 해결.
  - onData에서 IME 중 출력 무시 + 단독 호환 자모(U+3130–U+318F)는 누수로 보고 버림(첫 자모 leak 제거).
  - Enter는 직접 `\r` 보내지 않고 미러 종료 후 xterm에 위임 → `\r` 1회(이중 줄바꿈 해결).

## 파일 브라우저 시작 위치 = 터미널 cwd (원격)

- 셸이 디렉토리 변경 시 OSC 7(`\e]7;file://$PWD\a`)을 출력하도록 훅을 주입하고, 터미널이 `term.parser.registerOscHandler(7)`로 잡아 cwd를 추적(`TerminalHandle.getCwd`). 파일 브라우저 열 때 포커스된 (SSH) 패널의 cwd를 원격 시작 경로로 사용.
- **원격(SSH)**: 원격 rc 제어 불가 → 접속 후 OSC 7 훅을 런타임 주입. 배너/MOTD 보존을 위해 주입 직전 커서 위치 저장(ESC 7) → 셋업 끝에서 복원(ESC 8) + 아래만 지우기(ESC[J)로 에코된 셋업 줄만 제거.
- **로컬**: 파일 브라우저는 SSH에서만 열려 로컬 cwd는 쓰이지 않으므로 OSC 7 주입 안 함(주입 시도했던 rc/clear 방식은 cosmetic 문제로 전부 제거).
- **로컬 zsh `%` 표시**: 우리가 만든 게 아닌 zsh 기본 PROMPT_SP 동작(개행 없는 줄 표시). 로그인 메시지 없는 PTY 첫 프롬프트에서 드러남 → 로컬 zsh를 `+o promptsp`로 띄워 제거(rc/env 비침습).

## #31 — 세션 인계 시 스크롤백(이전 출력) 보존

- 백엔드: 세션별 출력 ring buffer `HistoryStore`(512KB 상한, 초과 시 앞부분 버림). pty/ssh가 같은 store 공유(세션 id는 고유 UUID). build_manager/build_state의 sink를 감싸 emit과 동시에 누적. 실제 kill 시 해당 세션 history 제거(인계 시엔 유지).
- 명령 `session_history(sessionId)` → 누적 출력 base64.
- 프론트(attach 모드): 화면 스냅샷 대신 history를 받아 `term.write`로 재생 → 분리 이전 스크롤백까지 복원. 실패/빈 값이면 스냅샷 폴백.
- 메모: 분리 직후 "첫 탭만 새창으로 뜸" 증상은 history 기능 적용(dev 재시작) 이전에 만들어진 세션이라 버퍼가 비었던 일시적 상태. 재시작 후 새 세션은 처음부터 누적되어 정상.
