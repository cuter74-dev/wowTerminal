## #82 — GlitchTip (Sentry SDK) error & crash tracking

GitHub #82 (English) / GitLab #1 (Korean).

### What / Why / How
- Goal: collect runtime errors/crashes from real users automatically via self-hosted GlitchTip (Sentry-compatible).
- **Server (user's Docker host)**: GlitchTip running at `https://glitchtip.oopnwow.com`. Org `oopnwow`, team `develop`, project `wowterminal` (id 1) created via the API. DSN: `https://663f23ace357492887f838d73b57a50c@glitchtip.oopnwow.com/1` (public ingest key — safe to embed).
- **Rust backend** (`src-tauri`): added the `sentry` crate (default-features off + `rustls` to avoid native-tls/openssl, matching the project's rustls usage). `init_error_tracking()` initializes at the very top of `run()` and the guard is held for the app lifetime so panics/errors are sent. Tag `component=backend`, `environment` = development/production by `debug_assertions`, `release` = `wowterminal@<version>` via `release_name!()`.
- **React frontend** (`src/main.tsx`): added `@sentry/react`, init before render, wrap `<App>` in `Sentry.ErrorBoundary`. Tag `component=frontend`, `environment` = `import.meta.env.MODE`, `release` = `wowterminal@${__APP_VERSION__}`. The version is injected at build time via a `define` in `vite.config.ts` (`__APP_VERSION__`, declared in `vite-env.d.ts`) because `getVersion()` is async and unusable at init time.
- **Single project, tag-distinguished**: backend/frontend share one DSN/project and are split by the `component` tag.
- **Opt-out**: an empty `WOWTERMINAL_GLITCHTIP_DSN` (Rust) / `VITE_GLITCHTIP_DSN` (frontend) disables tracking.
