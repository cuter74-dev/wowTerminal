# 2026-06-01 작업 로그

## #33 — 창 간 탭 재결합(드래그-병합) + 탭을 창 밖으로 드래그해 새 창

메인/보조 창 개념 없이, 어떤 창이든 다른 창으로 끌어다 놓으면 합쳐지고, 탭을 창 밖으로 끌어내면 그 위치에 새 창이 뜨도록.

### 무엇을 / 왜 / 어떻게
- **드래그-병합**(WKWebView는 창 간 DnD 불가 → OS 창 이동 감지 방식):
  - 모든 창이 `getCurrentWindow().onMoved`로 자기 이동을 감지 → 타이틀바 지점을 글로벌 이벤트 `wt://winpos`로 방송.
  - 각 창은 그 지점이 자기 영역 안이면 드롭 오버레이(`MergeDropOverlay`) 표시.
  - 이동이 멈추면(300ms 디바운스=release) `getAllWebviewWindows`로 대상 창을 찾아 `mark_session_detached`(백엔드 detach_guard)로 세션 보호 후 `wt://merge`{targetLabel,...} 전송 → 대상 창이 그 세션을 attach하는 탭 추가, 소스 창은 탭/창 닫기. 메인/분리 구분 없이 대칭.
- **탭을 창 밖으로 드래그 → 새 창**: 탭 pointer 드래그 시 커서가 창 경계 밖(또는 탭바 아래)으로 나가 떼면 분리. `open_detached_window`에 위치 x,y 추가 → 떼는 화면 좌표에 새 창 생성.
- **버그 수정**: 분리(attach 모드) 창은 spawn하지 않아 `onSession`을 호출 안 해 `sessionByLeaf`가 비었음 → 병합 시 세션을 못 찾고 새 셸을 띄워 내용이 사라짐. attach 모드에서도 `onSession(attachSessionId)`를 호출해 세션을 보고하도록 수정(연쇄 분리/병합에서 세션·스크롤백 유지).
- 백엔드: `mark_session_detached(sessionId, kind)` 명령(open_detached_window와 동일 detach_guard). capability에 `core:window:allow-close`/`allow-set-focus`, `core:event:allow-emit`/`allow-listen` 추가.

### 한계
- WKWebView가 창 밖 마우스 이벤트를 끝까지 전달하는지에 따라 "완전히 밖에서 떼기"가 안 될 수 있음(경계/탭바 아래 폴백 유지). 병합은 의도적 제스처(다른 창 위로 끌어다 놓기)에 맞지만 창을 단순히 겹쳐 놓을 때도 발동 가능.
