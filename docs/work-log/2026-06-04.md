## #75 — Korean IME double display during composition

### What / Why / How
- Symptom: during Korean composition a syllable is printed twice (찾→차차, 수정→수정정). Normalizes on commit/continued typing. Verified by extracting frames from a screen recording (.mov) with ffmpeg into an input-line montage.
- Cause: the latest WKWebView fires composition events, so xterm additionally renders the composing character in the .composition-view overlay. Our IME textarea mirror already sends the composing text to the PTY so the shell/TUI display it directly → the overlay overlaps = double.
- Fix: `.xterm .composition-view{display:none!important}` in App.css. Since the mirror handles PTY display, the overlay is redundant. User confirmed.

## #79 — Terminal not refitting on window resize

### What / Why / How
- Symptom: starting in a small window breaks the first prompt to ~2 columns and rows/cols stay small, and don't grow when the window is enlarged (screenshot).
- Cause: fit() in the ResizeObserver callback synchronously changes the element size → 'ResizeObserver loop' → in some environments subsequent notifications stop, halting refit. The initial fit may also run on an unsettled layout right after splash/onboarding.
- Fix (Terminal.tsx): wrap the RO callback in requestAnimationFrame (roRaf) → prevents the loop·keeps notifications. window 'resize' listener calls safeFit directly (fallback). RAF right after mount + 80ms/300ms refits correct the initial size. cleanup clears the listener/RAF/timers.
