## #151 — SFTP 다운로드 속도 개선 (병렬 range 읽기)

**문제**: `SftpManager::stream_download`가 64KB씩 **순차 동기 읽기**(한 번에 SFTP READ 하나, 왕복 대기)를 해서 고지연 링크에서 처리량이 `read_len/RTT`로 묶였다. (업로드는 russh_sftp File의 write_nowait로 이미 파이프라이닝됨 — 다운로드만 순차였다.) 또 진행 콜백이 매 64KB마다 Tauri 이벤트를 emit해 대용량 전송 시 IPC/UI가 병목.

**수정** (`src-tauri/src/ssh/sftp.rs`, `commands.rs`):
- `stream_download`: 파일을 연속 구간 N개(WORKERS=8)로 나눠(`split_ranges`) 각 구간을 별도 File 핸들로 스트리밍 → 동시에 N개의 READ가 떠 파이프가 찬다. 로컬 파일은 `set_len`으로 미리 확장, 각 워커가 원격·로컬을 자기 구간 시작으로 seek 후 순차 읽기/쓰기(겹침 없음). 진행은 공유 AtomicU64로 집계.
- 요청 버퍼 64KB → 256KB(순차 폴백·업로드 포함). russh_sftp가 서버 max read len으로 자동 캡.
- 작은/크기 미상 파일(<512KB)은 `stream_download_seq` 순차 폴백(구간 분할 이득 없음, 미상이면 EOF까지 읽어 안전).
- `commands.rs` progress sink: transfer_id별 40ms throttle(시작 0·완료 ≥total은 항상 emit)로 이벤트 폭주 차단.
- `split_ranges` 순수 함수로 분리 + 단위 테스트(빈틈·겹침 없이 [0,size) 전부 덮음).

**검증**:
- `cargo check` 통과. 프론트 `tsc --noEmit`·`vite build` 통과.
- `split_ranges` 로직 독립 검증(경계값 다수) 통과.
- **실서버 무결성 e2e**: 로컬 no-auth asyncssh SFTP 서버 20MB 랜덤 파일을 임시 example 바이너리로 병렬(8워커) 다운로드 → 순차본·원본과 **바이트 동일** 확인. (example은 커밋 안 함.)
- 참고: 순차 대비 처리량 이득은 RTT>0 실링크에서 나타남(localhost는 RTT≈0이라 속도차 없음). 무결성만 여기서 검증.

## #152 — 재접속 시 마지막 원격 디렉토리로 복귀

**문제**: SSH 연결이 끊긴 뒤 Enter로 재접속(#96)하면 새 셸이 `$HOME`에서 시작 — 이전 작업 위치를 잃음. `ssh_connect`는 로컬 pty_spawn과 달리 cwd 파라미터가 없다.

**접근**: 끊긴 뒤엔 원격을 조회할 수 없으므로 **살아있는 동안** 마지막 cwd를 캐시해야 한다. 이미 있던 `ssh_remote_cwd`(exec 채널 `/proc/<pid>/cwd` 조회 — rc 훅 불필요, 드래그 업로드용)와 OSC7 수신 핸들러를 재사용. 사용자 선택: **자동 추적**(권장) + **cd 보이게**(권장).

**수정** (`src/components/Terminal.tsx`, 프론트 전용):
- 효과 안에 `lastKnownCwd` 캐시. 출처 둘: OSC7 값이 오면 즉시 갱신, 그리고 onData에서 Enter(`\r`) 입력 시 `scheduleCwdProbe`(1.5s 디바운스 + 최소 3s 간격)로 `ssh_remote_cwd` 1회 조회해 갱신 — 상시 폴링 아님.
- Enter 재접속 시 `spawnFresh(lastKnownCwd)` 전달. SSH spawn 성공 후 500ms 뒤 `cd '<경로>'\r` 주입(PTY가 stdin 버퍼링하므로 프롬프트 전 주입도 안전). 경로는 `shQuote`로 단일 인용. cd는 화면에 보인다(사용자 선택).
- 효과 정리에서 probe 타이머 해제. 초기 접속(restoreCwd 없음)은 종전대로 홈/tmux.

**검증**: `tsc --noEmit`·`vite build` 통과. (실제 재접속 cd 복귀는 실서버 SSH에서 사용자 확인 예정.)
