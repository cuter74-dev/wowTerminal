## #183 — 파일 패널: SSH 재접속 뒤 "channel: canonicalize: session closed" (GitLab #82)

- 사용자 제보: "서버에 재 접속하니 파일 탭에 channel: canonicalize: session closed". 같은 제보에 "재접속하면 `cd '/workspace/newsj'`가 계속 Claude Code에 들어간다"도 있었다.
  - 확인해 보니 사용자 앱이 **0.21.3**(11-05부터 실행 중, 업데이트 미적용)이었다. #173 수정(0.21.4)이 들어 있지 않으니 업데이트하면 해결된다.
- 원인(#183): `SftpManager`가 호스트마다 SFTP 연결을 기억해 두고 `get_or_connect`가 살아 있는지 보지 않고 돌려줬다.
  - 네트워크가 끊기면 죽은 연결을 계속 써서 모든 요청이 "session closed"였다.
  - `withSftp`는 "session not found"일 때만 다시 연결했다.
- 어떻게:
  - `SftpConn::is_alive`: SSH가 닫혔거나 3초 안에 `canonicalize(".")`에 답하지 않으면 죽은 연결이다. `get_or_connect`는 죽었으면 버리고 새로 연결한다.
  - `conn()`은 닫힌 연결을 버리고 NotFound를 낸다. canonicalize·read_dir 실패가 닫힘 오류면 버리고 NotFound로 바꾼다. 그러면 기존 재시도가 다시 연결한다.
  - 프런트 `withSftp`는 `SFTP_RECONNECT_RE`(session not found·closed, channel·connection closed, disconnected, broken pipe)로 한 번 다시 시도한다.
- 시험:
  - Rust `closed_error_tests`.
  - e2e `sftp_e2e_reconnects_after_drop`(ignored): Docker 시험 서버(사용자 demo)에 붙은 뒤 `docker restart`로 끊는다. 다음 요청은 session not found가 되고, 다시 열면 새로 연결돼 동작한다. 실측 통과.
  - 프런트 fileDocs 2건(닫힘 오류에서 재연결, 권한 오류는 그대로).
  - 전체 vitest 90건, cargo 91건, 빌드 통과.
- 참고: 공용 작업 폴더에 다른 세션(wowterminal-ba, #182 DSN 교체)의 커밋 안 한 변경이 있다(CHANGELOG·PRIVACY·lib.rs·telemetry.rs·*.hold). 건드리지 않으려고 이 세션은 내 파일만 커밋하고, 배포 커밋은 별도 worktree에서 만든다.
