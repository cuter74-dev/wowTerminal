## SSH auth completed — agent delegation + password prompt + Keychain auto-save

Resolved, in order, the blockers hit while making real SSH connections per the plan. (Resolves the "v1 auth incomplete" limitation noted in work-log #5)

### 1. `ssh_connect` argument mapping bug
- Symptom: `missing field 'host_id'`. Tauri 2 converts only the top-level function argument names camel↔snake, but receives **struct inner fields via serde as-is**.
- Fix: `#[serde(rename_all = "camelCase")]` on `SshConnectArgs`.

### 2. ENETUNREACH (os error 51)
- Symptom: `connect: Network is unreachable`. Diagnostic logs found the port the user entered (10122) was actually unreachable (system ssh's `-P` is the PKCS#11 option, so it connected to the default 22, not the port). Changing to port 22, TCP connected.
- Hardening: explicitly resolve via `tokio::net::lookup_host` then sort IPv4-first before connecting — prevents IPv6-first/fallback issues in some environments.

### 3. ssh-agent delegated auth (`ResolvedAuth::Agent`)
- Connect `$SSH_AUTH_SOCK` via `russh::keys::agent::client::AgentClient` → `request_identities` → try `authenticate_publickey_with(user, pubkey, None, &mut agent)` for each `AgentIdentity::PublicKey`. Pass on the first success.
- Certificate credentials are unsupported in v1 (skipped). Clear error if the agent has no keys.

### 4. Password prompt (on-the-spot input, not stored)
- `SshAuthMethod::PasswordPrompt` variant + `SshError::PasswordRequired{host,port,user}` + `SshConnectError::PasswordRequired`.
- `password: Option<String>` in `ssh_connect` args. `resolve_auth` returns `PasswordRequired` if PasswordPrompt but no password.
- Frontend: `<PasswordPromptModal>` (🔐) — used in memory only, retry flow remounts via per-leaf `passwordByLeaf` + `retryNonce`.

### 5. Keychain auto-save
- Enabled `KeyringStore("wowterminal")` as the default secret store in `lib.rs` (macOS Keychain / Windows Credential Manager / Linux Secret Service).
- `ssh_remember_password(hostId, password)` command: store in keyring + update the host auth to `Password{secret_id=hostId}` → auto-auth from the next connection.
- Frontend: "Save to OS Keychain" checkbox in PasswordPromptModal. Save **only after a successful connection** via the `Terminal.onSshConnected` callback (a wrong password isn't saved). Clear the in-memory password/remember immediately after saving.

### Limitations
- Linux headless (no keyring daemon) → save fails; bundling the `EncryptedFileStore` (already implemented) fallback via a `CompositeStore` is a follow-up.
- Auto-cleanup of keychain entries on host delete is not implemented.

## LLM backend bugfixes (add doesn't register / 404)

### Add doesn't work and the existing one changes
- Cause: the backend identifier is the **id**, and picking the same preset twice gives the same id (`openai`) so `upsert` overwrites.
- Fix: reject + advise on duplicate id when saving a new backend. On preset selection, auto-suffix `-2`,`-3` on collision (based on `existingIds`).

### `http 404: {"detail":"Not Found"}`
- Cause: the user put `/v1/chat/completions` in `api_base` + **a trailing space**, so the `ends_with("/chat/completions")` check was false → `/chat/completions` duplicated.
- Fix: `.trim().trim_end_matches('/')` in the adapter `new`, trim `displayName/apiBase/defaultModel` on form save. Since the adapter cleans up on load, existing toml values are auto-corrected too.
- Note: macOS's `dirs::config_dir()` is `~/Library/Application Support` (not `~/.config`) — mind this when locating the config file.

## S-019~024 — SSH key management

### Backend (`ssh/keys.rs`)
- `KeyStore` (`keys.toml`): SshKeyEntry{id,name,algorithm,fingerprint,public_key,encrypted} CRUD. Private-key raw text in keyring (`id`=secret_id).
- Key generation: generate via the **system `ssh-keygen`** in a temp directory → read the PEM and store in keyring → delete the temp file. The `ssh-key` crate is used only for parsing (fingerprint/public_key).
- Key import: parse with `PrivateKey::from_openssh` + (when encrypted) verify by decrypt, store the raw PEM in keyring.
- Commands: `ssh_list_keys`/`ssh_generate_key`/`ssh_import_key`/`ssh_delete_key`.

### Why the external ssh-keygen command
- `ssh-key` 0.7-rc.10 depends on **rand_core 0.10** which removed `OsRng`, and the `CryptoRng` trait hierarchy (TryRng→Rng→CryptoRng) is complex, making it hard to pass a stable RNG directly. Tried wedging in rand_core 0.9 but the trait instance differs from the rand_core (0.10) that ssh-key uses → `CryptoRng` unsatisfied.
- Delegate only key generation to the OS standard tool (`ssh-keygen`, default on macOS/Linux/Win10+) and parse with the crate — avoids the rng dependency. The temp key file is deleted immediately.

### Frontend (`<SshKeyManager>`)
- Sidebar header 🔑 → modal. List/generate/import/details (copy public key)/delete/empty state.
- `<HostForm>` Private Key auth: secret_id text → changed to a **registered-key dropdown** (text fallback if none).

### Limitations
- Generated keys have no passphrase (`-N ""`) — protection is the keyring's job. Encrypted key import is supported but the passphrase secret_id at connect is manual.
- Generation is impossible where `ssh-keygen` is missing (rare) → import only.

## #24 — fix tab-detach session-handover bugs + hand over screen/AI conversation

`#20` still had the symptom "the new window opens but the existing terminal isn't handed over and a new session opens / typing doesn't work". Fixed 2 root causes and widened the handover scope to the screen·AI conversation.

### What / Why
- **Drag detach itself didn't work**: WKWebView (macOS) is unstable with HTML5 `draggable`/`drop` → made `TabBar` pointer-based (`onTabPointerDown`), and `App` triggers detach via mousemove/up + a threshold distance.
- **Handover session dies bug**: confirmed via logs `[ssh] kill` right after detach → `[ssh] write FAILED: session not found`. Causes = (1) the frontend `isSessionDetached` Set guard was nullified by dev HMR splitting the module instance, (2) **React StrictMode** ran the new window's attach Terminal as mount→unmount→mount, and the intermediate cleanup killed the handover session.
- **Starts with a blank prior screen**: the backend didn't buffer output so the new window had no past scrollback.
- **AI conversation not handed over**: the AIPanel conversation is component state so it didn't carry to the new window.

### How
- **Unify on backend detach protection**: `detach_guard: HashSet<SessionId>` + `mark_detached()` in `SshManager`/`PtyManager`. `open_detached_window` registers protection for the handover session → ignores the source window's first `kill` once (keeps the session). Removed the frontend `markSessionDetached`/`isSessionDetached`.
- **Removed StrictMode** (`main.tsx`): the dev double-run conflicted with PTY/SSH sessions·`detached_init`. It's absent in prod anyway, so behavior consistency improves.
- **Screen snapshot restore**: introduced `@xterm/addon-serialize`. Capture the source screen with `serialize()` right before detach → `open_detached_window(screen)` → `DetachedInit.screen` → restore via `term.write(screen)` on the new window's attach (skip Ctrl-L if a snapshot exists).
- **AI conversation handover**: AIPanel reports the active `sessionId` to App via `onActiveSession` (`aiSessionByTab`). On detach, `open_detached_window(aiSessionId)` → the new window's AIPanel restores the conversation from localStorage (shared across windows) via `initialSessionId`.
- Removed all debugging `eprintln!` (pty/ssh/windows).

## #22 — internationalization (11 languages)

UI string i18n. English default + Korean + Spanish/Chinese (Simplified)/Japanese/Russian/French/German/Vietnamese/Indonesian/Hindi (9 more).

### What / Why / How
- **Lightweight self-built i18n** (0 dependencies): `LangProvider` (Context) + `useT(dict)` hook in `src/i18n.tsx`. Each component holds a module-level local dictionary and picks the current-language bundle via `const t = useT(STR)`. Built ourselves instead of a library — lighter bundle and high cohesion since keys live next to the component.
- **Fallback type** `LangDict<T> = { en: T } & Partial<Record<Lang, T>>`: only English required, other languages optional. `useT` falls back via `dict[lang] ?? dict.en` → on a missing key only that item is English, never broken. A structure that lets languages be filled incrementally.
- **Language state**: `settings.general.language: Lang` (localStorage persisted). On first run `detectLang()` infers from the OS locale (en if unsupported). The settings dropdown is generated from the `LANGS` list (code + native name).
- **Wrapped App in `LangProvider`** (all 4 returns: bootstrap/splash/onboarding/normal). On language change the settings state changes → full rerender → immediate reflection.
- **Scope**: App + all components (host list/form, AI panel, terminal messages, SFTP file browser, key management, LLM setup, onboarding, security modals, tab/title bar, drop zone, settings) ~22 files. Each dictionary has 11 language blocks. Functional items (count/interpolation/ANSI messages) keep their signature·placeholders. Technical terms (SSH/SFTP/LLM/Keychain/JSON, etc.)·ANSI codes untranslated. Code comments kept in Korean.
- Translation work was split across 5 parallel sub-agent groups then integrated and build-verified.
