## SSH 인증 완성 — agent 위임 + password prompt + Keychain 자동 저장

기획서대로 실제 SSH 접속을 시키는 과정에서 막힌 것들을 순서대로 해결. (work-log #5에 적힌 "v1 인증 미완" 한계 해소)

### 1. `ssh_connect` 인자 매핑 버그
- 증상: `missing field 'host_id'`. Tauri 2는 함수 인자 최상위 이름만 camel↔snake 변환하고 **struct 내부 필드는 serde 그대로** 받음.
- 수정: `SshConnectArgs`에 `#[serde(rename_all = "camelCase")]`.

### 2. ENETUNREACH (os error 51)
- 증상: `connect: Network is unreachable`. 진단 로그로 확인 결과 사용자가 입력한 포트(10122)가 실제로 도달 불가였음 (시스템 ssh의 `-P`는 PKCS#11 옵션이라 포트가 아니라 기본 22로 붙었던 것). 포트 22로 바꾸니 TCP는 연결.
- 보강: `tokio::net::lookup_host`로 명시적 resolve 후 IPv4 우선 정렬해서 연결 — 일부 환경의 IPv6 우선/fallback 문제 예방.

### 3. ssh-agent 위임 인증 (`ResolvedAuth::Agent`)
- `russh::keys::agent::client::AgentClient`로 `$SSH_AUTH_SOCK` 연결 → `request_identities` → 각 `AgentIdentity::PublicKey`로 `authenticate_publickey_with(user, pubkey, None, &mut agent)` 시도. 첫 성공이면 통과.
- 인증서(Certificate) 자격증명은 v1 미지원(건너뜀). agent에 키 없으면 명확한 에러.

### 4. Password prompt (즉석 입력, 저장 안 함)
- `SshAuthMethod::PasswordPrompt` variant + `SshError::PasswordRequired{host,port,user}` + `SshConnectError::PasswordRequired`.
- `ssh_connect` args에 `password: Option<String>`. `resolve_auth`가 PasswordPrompt인데 password 없으면 `PasswordRequired` 반환.
- 프론트: `<PasswordPromptModal>` (🔐) — 메모리에서만 사용, retry 흐름은 leaf별 `passwordByLeaf` + `retryNonce`로 재마운트.

### 5. Keychain 자동 저장
- `lib.rs`에서 `KeyringStore("wowterminal")`를 기본 secret store로 활성화 (macOS Keychain / Windows Credential Manager / Linux Secret Service).
- `ssh_remember_password(hostId, password)` 커맨드: keyring에 저장 + 호스트 auth를 `Password{secret_id=hostId}`로 갱신 → 다음 접속부터 자동 인증.
- 프론트: PasswordPromptModal에 "OS Keychain에 저장" 체크박스. `Terminal.onSshConnected` 콜백으로 **접속 성공 후에만** 저장(잘못된 비밀번호는 저장 안 됨). 저장 후 메모리의 password/remember 즉시 클리어.

### 한계
- Linux headless(키링 데몬 없음)는 저장 실패 → `EncryptedFileStore`(이미 구현됨) 폴백을 `CompositeStore`로 묶는 작업이 후속.
- 호스트 삭제 시 keychain 항목 자동 정리는 미구현.

## S-025/033/034/028 — SFTP 파일 브라우저

- 전송: `download`(open→read_to_end→로컬 write), `upload`(로컬 read→create→write_all). 
- 파일 작업: `remove`(file/dir), `rename`, `mkdir`.
- 커맨드: `sftp_open`/`sftp_list`/`sftp_disconnect`/`sftp_download`/`sftp_upload`/`sftp_remove`/`sftp_rename`/`sftp_mkdir`, 로컬은 `local_list_dir`(std::fs, unix permissions mode).

### 프론트 (`<FileBrowser>`)

- 가운데 ← 다운로드 / → 업로드 (파일 선택 시 활성), 전송 중 표시.

## S-019~024 — SSH 키 관리

### 백엔드 (`ssh/keys.rs`)
- `KeyStore`(`keys.toml`): SshKeyEntry{id,name,algorithm,fingerprint,public_key,encrypted} CRUD. 개인키 원문은 keyring(`id`=secret_id).
- 키 생성: **시스템 `ssh-keygen`** 으로 임시 디렉토리에 생성 → PEM 읽어 keyring 저장 → 임시 파일 삭제. `ssh-key` crate로는 파싱(fingerprint/public_key)만.
- 키 import: `PrivateKey::from_openssh` 파싱 + (암호화 시) decrypt로 검증, PEM 원문을 keyring에 저장.
- 커맨드: `ssh_list_keys`/`ssh_generate_key`/`ssh_import_key`/`ssh_delete_key`.

### 왜 ssh-keygen 외부 명령인가
- `ssh-key` 0.7-rc.10이 의존하는 **rand_core 0.10**이 `OsRng`를 제거했고, `CryptoRng` trait 계층(TryRng→Rng→CryptoRng)이 복잡해 안정적인 RNG를 직접 넘기기 어려움. rand_core 0.9를 끼워봤으나 ssh-key가 쓰는 rand_core(0.10)와 trait 인스턴스가 달라 `CryptoRng` 불만족.
- 키 생성만 OS 표준 도구(`ssh-keygen`, macOS/Linux/Win10+ 기본)에 위임하고 파싱은 crate로 — rng 의존성 회피. 임시 키 파일은 즉시 삭제.

### 프론트 (`<SshKeyManager>`)
- 사이드바 헤더 🔑 → 모달. 목록/생성/가져오기/상세(공개키 복사)/삭제/빈 상태.
- `<HostForm>`의 Private Key 인증: secret_id 텍스트 → **등록된 키 드롭다운**으로 변경 (없으면 텍스트 fallback).

### 한계
- 생성 키는 패스프레이즈 없이(`-N ""`) — 보호는 keyring이 담당. 암호화 키 import는 지원하나 접속 시 passphrase secret_id는 수동.
- `ssh-keygen` 미설치 환경(드묾)에서는 생성 불가 → import만.
