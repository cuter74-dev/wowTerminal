## SSH 인증 완성 — agent 위임 + password prompt + Keychain 자동 저장

기획서대로 실제 SSH 접속을 시키는 과정에서 막힌 것들을 순서대로 해결. (work-log #5에 적힌 "v1 인증 미완" 한계 해소)

### 1. `ssh_connect` 인자 매핑 버그
- 증상: `missing field 'host_id'`. Tauri 2는 함수 인자 최상위 이름만 camel↔snake 변환하고 **struct 내부 필드는 serde 그대로** 받음.
- 수정: `SshConnectArgs`에 `#[serde(rename_all = "camelCase")]`.

### 2. ENETUNREACH (os error 51)
- 증상: `connect: Network is unreachable`. 진단 로그로 확인 결과 사용자가 입력한 포트(10122)가 실제로 도달 불가였음 (시스템 ssh의 `-P`는 PKCS#11 옵션이라 포트가 아니라 기본 22로 붙었던 것). 포트 22로 바꾸니 TCP는 연결.
- 보강: `tokio::net::lookup_host`로 명시적 resolve 후 IPv4 우선 정렬해서 연결 — 일부 환경의 IPv6 우선/fallback 문제 예방.

### 3. ssh-agent 위임 인증 (`ResolvedAuth::Agent`)
- `russh::keys::agent::client::AgentClient`로 `$SSH_AUTH_SOCK` 연결 → `request_identities` → 각 `AgentIdentity::PublicKey`로 `authenticate_publickey_with(user, pubkey, None, &mut agent)` 시도. 첫 성공이면 통과.
- 인증서(Certificate) 자격증명은 v1 미지원(건너뜀). agent에 키 없으면 명확한 에러.

### 4. Password prompt (즉석 입력, 저장 안 함)
- `SshAuthMethod::PasswordPrompt` variant + `SshError::PasswordRequired{host,port,user}` + `SshConnectError::PasswordRequired`.
- `ssh_connect` args에 `password: Option<String>`. `resolve_auth`가 PasswordPrompt인데 password 없으면 `PasswordRequired` 반환.
- 프론트: `<PasswordPromptModal>` (🔐) — 메모리에서만 사용, retry 흐름은 leaf별 `passwordByLeaf` + `retryNonce`로 재마운트.

### 5. Keychain 자동 저장
- `lib.rs`에서 `KeyringStore("wowterminal")`를 기본 secret store로 활성화 (macOS Keychain / Windows Credential Manager / Linux Secret Service).
- `ssh_remember_password(hostId, password)` 커맨드: keyring에 저장 + 호스트 auth를 `Password{secret_id=hostId}`로 갱신 → 다음 접속부터 자동 인증.
- 프론트: PasswordPromptModal에 "OS Keychain에 저장" 체크박스. `Terminal.onSshConnected` 콜백으로 **접속 성공 후에만** 저장(잘못된 비밀번호는 저장 안 됨). 저장 후 메모리의 password/remember 즉시 클리어.

### 한계
- Linux headless(키링 데몬 없음)는 저장 실패 → `EncryptedFileStore`(이미 구현됨) 폴백을 `CompositeStore`로 묶는 작업이 후속.
- 호스트 삭제 시 keychain 항목 자동 정리는 미구현.

## S-019~024 — SSH 키 관리

### 백엔드 (`ssh/keys.rs`)
- `KeyStore`(`keys.toml`): SshKeyEntry{id,name,algorithm,fingerprint,public_key,encrypted} CRUD. 개인키 원문은 keyring(`id`=secret_id).
- 키 생성: **시스템 `ssh-keygen`** 으로 임시 디렉토리에 생성 → PEM 읽어 keyring 저장 → 임시 파일 삭제. `ssh-key` crate로는 파싱(fingerprint/public_key)만.
- 키 import: `PrivateKey::from_openssh` 파싱 + (암호화 시) decrypt로 검증, PEM 원문을 keyring에 저장.
- 커맨드: `ssh_list_keys`/`ssh_generate_key`/`ssh_import_key`/`ssh_delete_key`.

### 왜 ssh-keygen 외부 명령인가
- `ssh-key` 0.7-rc.10이 의존하는 **rand_core 0.10**이 `OsRng`를 제거했고, `CryptoRng` trait 계층(TryRng→Rng→CryptoRng)이 복잡해 안정적인 RNG를 직접 넘기기 어려움. rand_core 0.9를 끼워봤으나 ssh-key가 쓰는 rand_core(0.10)와 trait 인스턴스가 달라 `CryptoRng` 불만족.
- 키 생성만 OS 표준 도구(`ssh-keygen`, macOS/Linux/Win10+ 기본)에 위임하고 파싱은 crate로 — rng 의존성 회피. 임시 키 파일은 즉시 삭제.

### 프론트 (`<SshKeyManager>`)
- 사이드바 헤더 🔑 → 모달. 목록/생성/가져오기/상세(공개키 복사)/삭제/빈 상태.
- `<HostForm>`의 Private Key 인증: secret_id 텍스트 → **등록된 키 드롭다운**으로 변경 (없으면 텍스트 fallback).

### 한계
- 생성 키는 패스프레이즈 없이(`-N ""`) — 보호는 keyring이 담당. 암호화 키 import는 지원하나 접속 시 passphrase secret_id는 수동.
- `ssh-keygen` 미설치 환경(드묾)에서는 생성 불가 → import만.

## #20 — 멀티 윈도우 세션 인계 (gh 설치 후 첫 정식 워크플로)

`gh` 설치 완료(2026-05-28) → 그동안 작업을 이슈 #9~#19로 소급 정리. 이번 작업부터는 이슈 먼저 생성(#20) → work-log → 커밋 → close.

- 탭 분리 시 새 윈도우가 같은 source로 **새 세션을 spawn**하던 것을, 기존 PTY/SSH **세션을 인계**하도록 변경.
- `terminalRegistry`: `markSessionDetached`/`isSessionDetached` set. 원본 Terminal cleanup이 detached 세션은 kill하지 않음.
- `Terminal`: `onSession`(spawn된 sessionId 보고), `attachSessionId`(있으면 spawn 대신 그 세션에 listen + resize). cleanup은 `isSessionDetached`면 kill skip.
- `windows.rs`: `open_detached_window`/`DetachedInit`에 `session_id` 추가.
- `App`: `sessionByLeaf` ref(leafId→sessionId), detach 시 sessionId 인계 + `markSessionDetached`, 분리 윈도우 부트스트랩 시 `attachSessionByLeaf`로 첫 leaf attach.

### 한계
- 분리 *시점 이전* 스크롤백은 새 윈도우에 미표시(백엔드가 출력 버퍼링 안 함 → 새 출력부터). 백엔드 ring buffer는 후속.

## #24 — 탭 분리 세션 인계 버그 수정 + 화면/AI 대화 인계

`#20`에서 "새 창은 뜨지만 기존 터미널이 인계되지 않고 새 세션이 뜬다 / 타이핑이 안 된다"는 증상이 남아 있었다. 근본 원인 2가지를 잡고, 인계 범위를 화면·AI 대화까지 넓혔다.

### 무엇을 / 왜
- **드래그 분리 자체 미동작**: WKWebView(macOS)는 HTML5 `draggable`/`drop`이 불안정 → `TabBar`를 pointer 기반(`onTabPointerDown`)으로, `App`은 mousemove/up + 임계 거리로 분리 트리거.
- **인계 세션이 죽는 버그**: 분리 직후 `[ssh] kill` → `[ssh] write FAILED: session not found` 로그로 확인. 원인 = (1) 프론트 `isSessionDetached` Set 가드가 dev HMR로 모듈 인스턴스가 갈려 무력화, (2) **React StrictMode**가 새 창 attach Terminal을 mount→unmount→mount로 이중 실행하며 중간 cleanup이 인계 세션을 kill.
- **이전 화면이 빈 채로 시작**: 백엔드가 출력을 버퍼링하지 않아 새 창엔 과거 스크롤백이 없었음.
- **AI 대화 미인계**: AIPanel 대화가 컴포넌트 state라 새 창엔 안 넘어감.

### 어떻게
- **백엔드 detach 보호로 일원화**: `SshManager`/`PtyManager`에 `detach_guard: HashSet<SessionId>` + `mark_detached()`. `open_detached_window`가 인계 세션을 보호 등록 → 원본 창의 첫 `kill`을 1회 무시(세션 유지). 프론트의 `markSessionDetached`/`isSessionDetached`는 제거.
- **StrictMode 제거**(`main.tsx`): dev 이중 실행이 PTY/SSH 세션·`detached_init`과 충돌. prod엔 원래 없어 동작 일관성↑.
- **화면 스냅샷 복원**: `@xterm/addon-serialize` 도입. 분리 직전 원본 화면을 `serialize()`로 캡처 → `open_detached_window(screen)` → `DetachedInit.screen` → 새 창 attach 시 `term.write(screen)`으로 복원(스냅샷 있으면 Ctrl-L 생략).
- **AI 대화 인계**: AIPanel이 활성 `sessionId`를 `onActiveSession`으로 App에 보고(`aiSessionByTab`). 분리 시 `open_detached_window(aiSessionId)` → 새 창 AIPanel이 `initialSessionId`로 localStorage(창 간 공유)에서 대화 복원.
- 디버깅용 `eprintln!`(pty/ssh/windows) 전부 제거.

## #22 — 다국어 지원 (11개 언어)

UI 문자열 i18n. 영어 기본 + 한국어 + 스페인/중국(간체)/일본/러시아/프랑스/독일/베트남/인니/힌디 9개 추가.

### 무엇을 / 왜 / 어떻게
- **경량 자체 i18n** (의존성 0): `src/i18n.tsx`의 `LangProvider`(Context) + `useT(dict)` 훅. 각 컴포넌트가 모듈 레벨 로컬 사전을 들고 `const t = useT(STR)`로 현재 언어 묶음을 고른다. 라이브러리 대신 자체 구현 — 번들 가볍고 키가 컴포넌트 옆에 있어 응집도 높음.
- **폴백 타입** `LangDict<T> = { en: T } & Partial<Record<Lang, T>>`: 영어만 필수, 나머지 언어는 선택. `useT`가 `dict[lang] ?? dict.en`으로 폴백 → 키 누락 시 그 항목만 영어로, 깨지지 않음. 언어를 점진적으로 채울 수 있는 구조.
- **언어 상태**: `settings.general.language: Lang` (localStorage 영속화). 첫 실행 시 `detectLang()`이 OS 로케일로 추정(미지원이면 en). `LANGS` 목록(코드+자국어 표기)으로 설정 드롭다운 생성.
- **App을 `LangProvider`로 래핑** (부트스트랩/splash/onboarding/정상 4개 return 모두). 언어 변경 시 settings 상태가 바뀌며 전체 리렌더 → 즉시 반영.
- **범위**: App + 전 컴포넌트(호스트 목록/폼, AI 패널, 터미널 메시지, SFTP 파일 브라우저, 키 관리, LLM 설정, 온보딩, 보안 모달들, 탭/타이틀바, 드롭존, 설정) 약 22개 파일. 각 사전에 11개 언어 블록. 함수형 항목(카운트/보간/ANSI 메시지)은 시그니처·플레이스홀더 유지. 기술 용어(SSH/SFTP/LLM/Keychain/JSON 등)·ANSI 코드는 비번역. 코드 주석은 한국어 유지.
- 번역 작업은 병렬 서브에이전트 5그룹으로 분담 후 통합 빌드 검증.
