## #170 — 떠났다 돌아와 한글로 이어 쓰면 앞 글이 전부 지워짐

사용자 제보: Claude Code 입력창에 글을 써 두고 한참 뒤 이어 쓰면 기존 글 전체가 삭제. "Claude Code 버그인지 터미널 버그인지 모르겠다."

### Claude Code 단독 실험 → 원인은 터미널
pyte(파이썬 터미널 에뮬레이터) + PTY로 Claude Code(2.1.318)만 실행:
- `hello 안녕하세요 테스트` 입력 → 75초 대기 → `Z` → `…테스트Z` 그대로.
- Claude Code는 포커스 보고(?1004h)를 켜는데, `ESC[O`·`ESC[I`를 보내도 글 유지.

### 원인
- 이 맥은 한글 미러 경로(로컬 진단 `wt.ime.local-diag`: mirrorChars 52,041).
- blur 때 xterm이 helper textarea를 비운다(`_handleTextAreaBlur`). #159는 "포커스 잃음" 표시 후 **다음 keydown**에서 기준선을
  맞췄는데, 229-only 맥의 한글 키는 **beforeinput → input → keydown(229)** 순서(실기기 녹화 그대로) → 돌아와 첫 키가 한글이면
  input의 미러 diff가 먼저 돌아 빈 textarea와 옛 기준선(줄 전체)을 비교 → `\x7f`×N. #159 녹화는 돌아온 첫 키가 스페이스였다.

### 수정
- 값이 바뀌기 직전인 `beforeinput`에서도 기준선을 맞춘다(keydown과 공용 `rebaselineAfterFocusLoss`, 먼저 오는 쪽 한 번).

### 검증
- 합성 재생 T9(실기기 순서): 수정 전 줄 `하`, 수정 후 `안녕하`. 변이(beforeinput 제거) 시 실패.
- **실기기 e2e(실제 한글 2벌식 IME)**: HID 키 이벤트(CGEvent, 하드웨어와 같은 경로)로 격리 HOME 테스트 앱에 입력, 셸 대신
  원시 바이트 기록기. 수정 전 `…녕\x7f\x7fㅎ\x7f하` → `하`(2회 재현), 수정 후 `…녕ㅎ\x7f하` → `안녕하`.
- npm test 45(+2 skipped).

### 사고와 정리 (중요)
- Orca `--restore-window`(번들 id·pid 지정 모두)가 앱을 못 찾으면 **같은 번들 id의 빌드 폴더 번들을 실제 HOME으로 띄웠다**(2회).
  그 인스턴스가 **사용자의 실제 세션 데몬**에 붙어 새 셸을 만들었다. 1회차에는 HID 키(`ㅏㄴ녕하`, Enter)가 그 새 셸로 들어가
  "command not found"만 났다(파일 변화 없음). 2회차는 frontmost pid 안전 검사가 키 전송을 막았다.
- 정리: 데몬 읽기 전용 질의로 세션 목록을 대조하고, 사용자 앱 스냅샷에 없는 **스트레이 앱이 만든 세션만** 종료
  (1회차: 탭 닫기로 685d84cf, 대체 셸 f903e0ea는 pty_kill / 2회차: d8c844d9 pty_kill). 최종 7개 — 사용자 세션(스냅샷의 5개 등) 모두 유지.
- 재발 방지: 테스트 번들 LaunchServices 등록 해제·빌드 폴더 번들 삭제, `--restore-window` 대신 System Events로 **pid 지정 활성화**,
  키 전송 전 frontmost pid 확인.
- 참고: 사용자 데몬은 아직 **0.20.16(프로토콜 1)** — 세션이 있어 교체되지 않았다. 그래서 #160(SSH 세션 유지)·#168(로컬 작업 폴더)
  기능은 로컬 셸을 모두 닫아 데몬이 교체될 때까지 동작하지 않는다.
