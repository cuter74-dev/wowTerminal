# 2026-11-20 작업 기록

## #195 — 삭제 확인 창이 뜨지 않음, 처리 안 된 IPC 거부 (GitLab #94)

**무엇:**
- 삭제하기 전에 다시 묻는다. 지금까지 macOS·Windows·Linux에서 SSH 그룹·태그·키, AI 백엔드, 파일 브라우저의 서버 파일·폴더를 지울 때 확인 창 없이 바로 지워졌다.
- 셸이나 SSH 연결이 막 끝난 터미널에 입력하거나 크기를 바꿀 때 나던 처리 안 된 오류를 받아 넘긴다.
- 오류 보고에 공통 머리말 대신 실제 오류 글이 실리고, 세션 id는 `<id>`로 가려 같은 원인이 한 이슈로 묶인다.

**왜:** 총괄의 주간 지표(11-13 → 11-20)에 처리 안 된 Promise 거부 8건이 "값: C / s / c"처럼 한 글자로 올라왔다. 요약이 제목을 잘라서 그렇게 보였을 뿐이고, GlitchTip에 저장된 전체 값은 다음과 같았다.
- 4건(0.22.2, Windows): `Command plugin:dialog|confirm not allowed by ACL`
- 3건(0.22.1, macOS): `session not found: <세션 id>`
- 1건(0.22.1, macOS): `channel: session terminated`

첫 번째가 실제 버그였다. dialog 플러그인 2.7.1은 Android를 뺀 모든 플랫폼에서 `window.confirm`을 비동기 함수로 바꿔 넣는다. 그 함수는 이제 없는 명령(`plugin:dialog|confirm`)을 불러 권한 검사에서 거부된다. 그런데 우리 코드의 `if (!confirm(…)) return;`은 Promise를 받는데, Promise는 참이라 묻지 않고 그대로 지웠다. 나머지 두 개는 끝난 세션으로 보낸 크기 맞춤·입력이 거부된 것으로, 예상된 일인데 받는 곳이 없었다.

**어떻게:**
- `src/askConfirm.ts`: 플러그인의 `confirm()`을 기다리는 도우미다. 이 함수는 허용된 `message` 명령으로 네이티브 확인 창을 띄운다. 창을 못 띄우면 "아니오"로 본다. 삭제 여섯 곳을 이것으로 바꿨다.
- 시험(`src/askConfirm.test.tsx`)
  - 실제 앱처럼 바뀐 `window.confirm`을 둔 채 그룹 삭제에서 "아니오"면 지우지 않고 "예"면 지우는지 본다. 고치기 전 코드에서는 "아니오"인데도 지워져 실패한다.
  - 코드에 맨 `confirm(`이 다시 들어오면 실패한다.
- `src/components/Terminal.tsx`: 크기 맞춤, `sendInput`(AI 패널·에이전트 목록), 분리 창 인계 뒤 크기 맞춤에 `.catch`를 달았다. 시험 `src/closedSession.test.tsx`로 처리 안 된 거부가 남지 않는지 본다.
- `src/telemetry.ts`: Sentry가 문자열 거부에 붙이는 머리말을 떼고 UUID를 가린다(`src/telemetry.test.ts`).
- 전체 JS 시험 186개 통과. 실제 앱에서 확인 창이 뜨는지는 아직 보지 않았다(사용자가 자리를 비울 때 격리 시험 앱으로 확인).
