## #84 — Korean input completely broken on Windows (v0.13.0 regression)

GitHub #84 (English) / GitLab #3 (Korean).

### What / Why / How
- Symptom: after v0.13.0, Hangul could not be typed at all on Windows.
- Cause: the #83 IME fix added a `compositionstart` → `nativeComposition` bypass that disables the custom IME mirror and lets xterm handle IME natively. It targeted the newest macOS WKWebView, but **Windows WebView2 (Chromium) always fires composition events**, so the bypass triggered there too — disabling the mirror that Windows depends on, and xterm's native path doesn't input Korean on Windows.
- Fix (`Terminal.tsx`): gate the bypass to macOS only via `const isMacWebView = navigator.userAgent.includes("Mac")`. The `compositionstart` listener is registered only when `isMacWebView`; on Windows/Linux `nativeComposition` stays false, so the keyCode-229 path keeps using the custom mirror exactly as in v0.12.0. macOS keeps the newest-WKWebView bypass from #83.
- `npm run build` ✅. Windows fix is logically a restoration of the pre-#83 path (mirror) — verified by reasoning; macOS path unchanged.
