# 2026-05-27 작업 로그

## fix(build) — 누락된 `secrets` 모듈 복원 + `.gitignore` 정정

이슈: 별도 생성 안 함 (시스템에 `gh` 미설치, 후속에 만들 예정).

### 무엇을
- `src-tauri/src/secrets/` 디렉토리를 work-log 2026-05-22 #3 명세대로 복원
  - `mod.rs` — `SecretStore` trait, `SecretError`, `Secret = Zeroizing<Vec<u8>>`
  - `keyring_store.rs` — OS 키링 어댑터 (`keyring` 3.x, 임의 바이트는 base64 wrap)
  - `encrypted_file.rs` — Argon2id(m=64MiB / t=3 / p=1, 32B) + AES-256-GCM, AAD=id, TOML 형식
- `.gitignore`의 `secrets/` 패턴은 보안 보호망으로 유지하되, `!src-tauri/src/secrets/` 예외 추가
- `EncryptedFileStore` 테스트 6개 복원 (roundtrip / overwrite / delete 멱등 / bad passphrase / tampered ct / AAD swap)

### 왜
- `git check-ignore`로 확인: `.gitignore`의 `secrets/` (라인 41)가 너무 광범위해 `src-tauri/src/secrets/mod.rs`까지 매치 → 코드 디렉토리가 한 번도 추적된 적 없음 (`git log -- src-tauri/src/secrets` 비어 있음).
- 그 결과 `lib.rs`의 `pub mod secrets;` 선언과 `ssh/commands.rs`의 `use crate::secrets::{EncryptedFileStore, SecretStore};`가 빈 모듈을 가리키는 상태. `cargo build` 시 `error[E0583]: file not found for module 'secrets'` 발생, tauri 윈도우 못 띄움.
- 보안 의도(시크릿 값이 들어간 `secrets/` 디렉토리는 어디 있든 무시)는 유지하면서 코드 모듈만 예외 처리하는 게 `secrets/` → `/secrets/`(루트 anchored)보다 안전. 사용자가 임의 위치에 시크릿 디렉토리를 떨궈도 잡힌다.
- 모듈 자체는 work-log #3에 인터페이스와 디스크 형식이 명세되어 있어 그대로 재구현.

### 어떻게
1. `.gitignore` 수정
   ```diff
    secrets/
   +# code module — secrets/ pattern above must not hide it
   +!src-tauri/src/secrets/
   ```
   `git check-ignore -v src-tauri/src/secrets/mod.rs` → "NOT ignored" 확인.
2. **`SecretStore` trait** (`mod.rs`)
   - `save(&self, id, &[u8])` / `load(&self, id) -> Result<Secret>` / `delete(&self, id) -> Result<()>`
   - `delete`는 없는 키도 Ok (멱등).
   - `Send + Sync` (dyn으로 `Arc<dyn SecretStore>`에 들어가기 위함).
3. **KeyringStore**
   - `Entry::new(service, id)` → `set_password(base64)` / `get_password()` / `delete_credential()`
   - `KeyringError::NoEntry` → `SecretError::NotFound`, delete는 멱등.
4. **EncryptedFileStore**
   - `open_or_create(path, passphrase)`: 파일 없으면 16B salt 새로 만들어 빈 TOML 작성.
   - KEK = Argon2id(passphrase, salt, m=64MiB / t=3 / p=1, 32B 출력).
   - `save`: nonce 12B 생성 → `AES-256-GCM(kek).encrypt(nonce, Payload { msg, aad=id })` → base64로 TOML에 기록.
   - `load`: AEAD 실패 / base64 디코드 실패 / nonce 길이 이상 모두 `BadPassphrase`로 통합. 항목 없으면 `NotFound`.
   - `delete`: 인메모리 + 디스크에서 제거, 항목 없으면 디스크 write 생략.
   - 동시성: `Mutex<FileFormat>`로 인메모리 상태 보호. 디스크 IO는 매 mutate마다 전체 write (간단, 시크릿 수가 적은 워크로드 가정).
   - KEK는 `Zeroizing<Vec<u8>>`에 보관 → drop 시 자동 zeroize.

   - `cargo test --lib` ✅ — **40 passed** (AI 9 + PTY 4 + SSH store 5 + SSH session 10 + known_hosts 6 + secrets 6)
