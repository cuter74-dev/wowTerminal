## feat(ui) — S-011 terminal split (pane tree)

Issue: not created.

### What
- Redefined the `Tab` data model: `{ id, label, root: Pane, focusedPaneId }`. Removed the old `source` field.
- `Pane` type:
  ```ts
  type Pane =
    | { kind: "leaf"; id: string; source: TerminalSource }
    | { kind: "split"; direction: "vertical" | "horizontal"; ratio: number; first: Pane; second: Pane };
  ```
- New component `PaneView` — recursively renders the pane tree, leaf = header (label+×) + Terminal, split = two children + a drag divider
- Helpers in `types.ts`: `findLeaf`, `collectLeaves`, `firstLeafId`, `splitLeaf`, `removeLeaf`, `setRatioByPath`, `neighborLeafId`
- App actions: `splitActivePane(direction)`, `closePane(tabId, leafId)`, `focusPane`, `setPaneRatio`, `focusNeighborOrSwitchTab`
- Shortcuts:
  - `Ctrl+Shift+L` — split left-right (vertical)
  - `Ctrl+Shift+S` — split top-bottom (horizontal). The wireframe had `Ctrl+Shift+D` but it collides with 'duplicate tab' → moved to S
  - `Ctrl+Shift+arrow` — if a split exists, focus the adjacent pane, else move the tab left/right
- Wired the `TabContextMenu` "Split (left-right / top-bottom)" item to its real action
- Updated `TabBar` / `TitleBar` / `AIPanel` to the new data model:
  - Tab icon: based on source if a single leaf, ⊟ if split
  - AIPanel: shows the *focused pane's* source in the active tab as context

### Why
- Wireframe-specified: showing two sessions of the same host in one tab for patterns like "one tails logs, the other runs commands" is a core flow
- Why model panes as a tree: recursive splitting (later nested split) is naturally expressed, and split/merge doesn't affect other leaf state (PTY sessions)
- Using the leaf id as the React key keeps the same leaf as the same component instance across split/merge → prevents session re-spawn
- `Ctrl+Shift+arrow` moves pane focus when split, auto-falls back to tab move when not split: one shortcut handles both use cases (the user needn't be aware of split state)

### How
1. `Pane` tree helpers (`types.ts`)
   - `splitLeaf(root, targetId, newLeaf, direction)`: replace the target leaf with a split node, first child = the old leaf, second = the new leaf, ratio 0.5
   - `removeLeaf(root, targetId)`: replace the parent split with the sibling leaf. If the root is a single leaf → `null` (caller delegates to closing the tab)
   - `neighborLeafId(root, focusedId, direction)`: walk up the focused leaf's ancestor chain to find a suitable split, then jump to the opposite child's first/last leaf
2. `PaneView` (`components/PaneView.tsx`)
   - leaf: header (only when split) + Terminal. The focused leaf gets a 1px blue outline + header-background highlight
   - split: flex container (`flexDirection: row|column`) + two children + a 4px divider
   - Divider drag: mousedown → window mousemove → compute ratio against the container rect (minimum 120px) → end on mouseup
3. App flow
   - `splitActivePane`: split into a new leaf copying the focused leaf's source as-is. Focus moves to the new leaf
   - `closePane`: if a leaf inside a split, replace with the sibling; if a single leaf, delegate to closing the tab itself
   - On host single-click, the source change targets only the focused leaf. Other panes unaffected

### Verification
- `npm run build` ✅ — 0 errors, bundle 560KB (gzip 155KB)
- Manual GUI: menu "Split (left-right / top-bottom)" / Ctrl+Shift+L / Ctrl+Shift+S → split works, divider drag resize, close via the pane header's ×, header disappears when reduced to a single leaf, Ctrl+Shift+arrow moves pane focus — needs confirmation.

### Notes / Limitations
- `Ctrl+Shift+D` shortcut collision: in the wireframe 'duplicate tab' and 'split top-bottom' share the key. We keep duplicate and moved split to `Ctrl+Shift+S`. Menu text stays consistent without showing the shortcut.
- On split, the new leaf copies the existing leaf's source (e.g. the same SSH host). To start with a different host, change the source via single-click.
- During divider drag, xterm's ResizeObserver calls fit() frequently — not a big burden, but room to throttle later.
- Independent per-pane PTY sessions are guaranteed, so terminating one pane doesn't affect another.

### Next steps
- S-008/009 (drag detach + multi-window): introduce Tauri `WebviewWindowBuilder`, inter-window IPC, a session-handover mechanism (the PTY is single-owned by the backend, so between windows only the view needs to move)

## feat(ui+core) — S-008/009 tab drag detach + multi-window

Issue: not created.

### What
- New Rust module `src-tauri/src/windows.rs`
  - `DetachedRegistry`: `Mutex<HashMap<window_label, DetachedInit>>`. Holds the new window's initial source/label
  - Tauri command `open_detached_window(source, label_hint) -> window_label`: assigns a `detached-{uuid8}` label, stores in the registry, opens an empty `index.html` via `WebviewWindowBuilder`
  - Tauri command `detached_init() -> Option<DetachedInit>`: looks up the registry by the calling window's label, takes and removes the entry
- Added `pub mod windows;` + `DetachedRegistry::default()` manage + 2 invoke handlers to `src-tauri/src/lib.rs`
- Extended the `windows` matcher in `src-tauri/capabilities/default.json` to `["main", "detached-*"]` (grants the same capability to new windows)
- Frontend
  - `App.tsx` bootstrap: decide detached-ness synchronously via `getCurrentWindow().label` → if detached, start with empty tab state, call `detached_init` in a `useEffect` → build the first tab from the received source → `bootstrapped=true`
  - Before bootstrap, a "Initializing detached window…" splash
  - Wired the context-menu "Detach to new window" to its real action (`detachLeafToNewWindow`)
  - Drag detach: `draggable + onDragStart/End` on the `TabBar` tabs. `draggingTabId` state + `<DropZoneOverlay>` in App — a translucent + dashed overlay over the main area while dragging, on drop call the backend + close the source, ESC to cancel

### Why
- Core interaction of wireframe S-008/009 — without multi-window, patterns like "prod/staging on two monitors separately" are impossible.
- Why pass the source via `DetachedRegistry` instead of a URL query: PathBuf+query string behaves differently between dev/prod and is weak to escape issues. A backend in-memory registry + one invoke is simple and reliable.
- Why detached-ness must be known *synchronously*: if not decided at the useState initial value, the first tab temporarily spawns → kills → re-spawns with the new source, creating a race; if a fast cleanup runs before spawn completes, a zombie PTY can remain.
- Why HTML5 native `draggable`: the browser handles the drag ghost and cursor change automatically. Minimal code vs a custom mouse tracker.

### How
1. **Backend**
   - `DetachedSource` enum (Local / Ssh{host_id}) — Serialize+Deserialize, `#[serde(tag="kind", rename_all="lowercase")]`. Directly compatible with the frontend `TerminalSource`
   - `open_detached_window`: clean up the registry entry on builder failure (cleanup-on-failure)
   - `detached_init`: *takes and removes* the entry — even if re-called on a window refresh, the second call is None
2. **Frontend**
   - `IS_DETACHED_WINDOW` constant: decided at module top-level via `getCurrentWindow().label.startsWith("detached-")`
   - `bootstrapped` state — starts false if detached, true when the init effect completes
   - Relaxed the `activeTabId` type to `string | null` (null before detached boot). Added null guards to the keyboard handler
   - `detachLeafToNewWindow(tabId)`: call `open_detached_window` with the given tab's focused-leaf source → on success close the source leaf/tab
   - The context menu onDetach calls the above (disabled in the menu for a single leaf; for a split leaf only the pane detaches)
   - `<DropZoneOverlay>`: the whole area below the tab bar, `position: fixed; inset: 66px 0 0 0`. `onDragOver=preventDefault`, `onDrop=getData(TAB_DRAG_MIME)` extracts tabId then detaches
3. **capability**
   - `windows: ["main", "detached-*"]` glob matcher. New windows get the same permission scope

### Verification
- `cargo check` ✅ (13s)
- `cargo test --lib` ✅ — **40 passed** (no regression)
- `npm run build` ✅ — 0 errors, bundle 576KB (gzip 159KB)
- Manual GUI:
  - Tab right-click → "Detach to new window" → new window opens + source tab/pane closes
  - Drag a tab below the tab bar → translucent drop zone + dashed border, new window on drop
  - ESC cancels the drop
  - The new window spawns a new session from the received source — keeps a label like `label (copy)`

### Notes / Limitations
- **Session handover not implemented**: the new window *spawns a new PTY/SSH session* from the received source info. The wireframe's "prod-server-01 session preserved 12:34 after detach" can't be expressed in v1. Real handover needs the new window to receive the existing sessionId, and a mode where the source skips the kill call on cleanup. The PTY manager is Tauri global state, so listening works from any window once it knows the sessionId — reachable as a follow-up
- **Drag ghost**: browser default — the wireframe's "translucent tab preview" is drawn automatically as an element snapshot and looks natural. A custom ghost is possible later
- **On window close**: closing the new window → Terminal cleanup → session terminates. A close-confirm dialog is not implemented
- **macOS menu/command key**: shortcuts handled as `ctrl||meta` OR. Both macOS's ⌘ and ctrl work
- A single tab + split tree disables the menu's "Detach to new window" — per the wireframe rule (`disable detach-to-new-window when it's the only tab`). A fine-tune to enable it only for single tab + split is a follow-up

### Next steps
- Session handover (move PTY/SSH sessions between windows): an `attachExistingSessionId` mode in Terminal + a skip-kill option on the source's cleanup
- Move tabs between windows (S-009's "drag a tab to another window")
- S-012~018 (SSH host management pool): search/filter/group/tag/empty state, or in the user's preferred order

## feat(ui) — S-013/016/018 host search·sort·delete-confirm·empty state

- On host delete, swap every tab/pane leaf pointing at that host to a local shell → SSH sessions clean up properly (Terminal remount)

### Why
- Explicit requirements of wireframe S-013/016/018
- The old behavior where host delete was decoupled from active SSH sessions is risky — telling the user "N sessions currently active" in the modal and proceeding after explicit consent prevents accidents

### How
- Cache the search+sort result with `useMemo`. The search keyword does substring matching on a single string joining `name + user@host:port + tags` (simple)
- Sort is client-side `localeCompare`. "Most recent connection" sort is later (the backend has no time info yet — when `hosts.toml` gets a last_used field)
- `<DeleteHostModal>` is red-toned, gray notice if 0 active sessions, a `#3a1d1d` warning box if ≥1
- The empty state shows only when there's no search query — if search results are 0, only "No search results" is shown (no CTA)
- After host delete, `detachHostFromAllTabs` recursively scans the whole tree and swaps only `ssh:hostId` leaves to local (works even if only some panes inside a split tree match)
- Track query/sort/tabs accurately via TS `useMemo`/`useCallback` dependencies
