## #129 — 세션 단위 사고력(reasoning) 오버라이드 + 스트리밍 경로 누락 수정

### What / Why
- #123에서 백엔드 등록 시 `reasoning_effort`를 넣었지만, **AI 패널은 항상 스트리밍으로 요청**하는데 주입이 비스트리밍 경로에만 있었다 → 설정이 조용히 아무 일도 하지 않고 있었다.
- 또 강도 값이 프로바이더마다 다르다(GLM `max`, OpenAI `minimal`). low/medium/high 고정 드롭다운으로는 표현이 안 돼 자유 입력으로 바꿔야 했다.
- 대화마다 강도를 바꾸고 싶다는 요구 → 요청 단위 오버라이드.

### How
- `ai/types.rs`: `ChatRequest.reasoning_effort: Option<String>` 추가.
- `ai/adapters/openai_compat.rs`: `effective_reasoning()` — **요청 값 우선, 없으면 백엔드 등록값**으로 폴백. 비스트리밍·**스트리밍 양쪽 모두**에 주입(#123 누락분 수정).
- `ai/registry.rs`: 스트리밍 호출부에 값 전달.
- `src/components/AIPanel.tsx`: 🧠 드롭다운(auto/minimal/low/medium/high/max) — 세션 단위로 적용, auto면 백엔드 설정값 사용.
- `src/components/LlmSetupModal.tsx`: 등록 필드를 고정 드롭다운 → **datalist 제안이 붙은 자유 입력**으로 변경(프로바이더 고유 값 통과).
- `src/types.ts`: `ChatRequest.reasoning_effort` 반영.

## #130 — 생성 중 ＋(새 대화) 버튼이 먹통으로 보이던 문제

### What / Why
- 스트리밍 생성 중에 ＋를 누르면 패널이 비워졌다가 **진행 중이던 스트림 콜백이 옛 대화를 계속 다시 그려서** 버튼이 죽은 것처럼 보였다. 세션 전환도 같은 증상.

### How
- `src/components/AIPanel.tsx`: **chat epoch ref** 도입 — ＋ 또는 세션 전환 시 epoch을 증가시키고, delta/done/error 콜백은 자신이 시작된 epoch과 다르면 결과를 버린다. 늦게 도착한 콜백이 새 화면을 오염시키지 못한다.
