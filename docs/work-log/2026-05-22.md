# 2026-05-22 작업 로그

## #2 — OpenAI 호환 AI 어댑터 구현

이슈: https://github.com/cuter74-dev/wowTerminal/issues/2

### 무엇을
- `AiBackend` 트레잇의 첫 구현체로 `OpenAiCompatibleBackend` 작성.
- 다중 백엔드 관리용 `AiRegistry` (id → 구현체 매핑).
- 백엔드 설정 데이터 모델 `BackendConfig` / `OpenAiCompatibleConfig`.
- 프론트엔드용 Tauri command `ai_list_backends`, `ai_complete`.
- HTTP 클라이언트(`reqwest` rustls), URL/UUID 의존성 추가.
- `wiremock` 기반 단위/통합 테스트 9개 추가, 모두 통과.

### 왜
- 첫 어댑터를 "OpenAI 호환"으로 선택한 이유는 **하나의 코드로 외부(OpenAI 본가) + 자체 호스팅(vLLM/TGI/Together) + 로컬(Ollama OpenAI 엔드포인트)을 동시에 커버**할 수 있기 때문이다. 어댑터 수를 늘리지 않고 가장 많은 환경을 지원.
- `AiRegistry`를 도입한 이유: 프론트는 `backend_id` 문자열로만 백엔드를 지정하고, 백엔드 인스턴스의 라이프사이클/락은 백엔드 코드 한 곳에서만 관리되도록 책임 분리.

### 어떻게
1. **의존성 추가** (`src-tauri/Cargo.toml`)
   - `reqwest = { version = "0.12", default-features = false, features = ["rustls-tls", "json", "stream"] }`
   - `url`, `uuid`(v4), `futures-util`
   - `[dev-dependencies]`: `wiremock = "0.6"`, `tokio` macros/test-util.
2. **모듈 구조**
   ```
   src-tauri/src/ai/
   ├── mod.rs              # AiBackend 트레잇, prelude
   ├── types.rs            # Message/ChatRequest/ChatResponse/AiError/TokenUsage
   ├── config.rs           # BackendConfig (enum) + OpenAiCompatibleConfig
   ├── registry.rs         # AiRegistry: HashMap<String, Arc<dyn AiBackend>>
   ├── commands.rs         # Tauri command: ai_list_backends, ai_complete
   └── adapters/
       ├── mod.rs
       └── openai_compat.rs   # OpenAiCompatibleBackend
   ```
3. **어댑터 구현 포인트**
   - 외부 도메인 모델(`ChatRequest`/`ChatResponse`)과 OpenAI wire format(`OpenAiChatRequest`/`OpenAiChatResponse`)을 분리해 어댑터가 변환 담당.
   - HTTP 401/403 → `AiError::Auth`, 429 → `AiError::RateLimited`, 5xx → `AiError::Backend("server ...")`.
   - `api_key`가 `None`이면 `Authorization` 헤더를 생략 (인증 불필요 로컬 서버 지원).
4. **레지스트리**
   - `Arc<RwLock<HashMap<String, Arc<dyn AiBackend>>>>` 로 멀티스레드 안전.
   - `complete()`은 RwLock의 read guard에서 `Arc<dyn AiBackend>` clone 후 락 해제 → trait 호출.
5. **Tauri 통합**
   - `lib.rs`의 `Builder::default()`에 `.manage(AiRegistry::new())` 추가.
   - `invoke_handler`에 `ai_list_backends`, `ai_complete` 등록.
6. **검증**
   - `cargo check` ✅
   - `cargo test --lib` ✅ (9 passed, 0 failed)
     - happy path JSON 파싱
     - 401 → Auth, 429 → RateLimited, 503 → Backend
     - choices 비어있을 때 → InvalidResponse
     - api_key None일 때 헤더 미포함
     - 레지스트리 register/list/dispatch
     - 알 수 없는 backend_id → Backend 에러
     - 레지스트리 + OpenAI 호환 어댑터 + wiremock 통합
