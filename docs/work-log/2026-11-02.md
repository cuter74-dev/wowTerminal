## #169 — 창 닫기(X)가 0.21.0부터 동작하지 않음

사용자 제보: Windows에서 창 상단 X로 프로그램이 종료되지 않는다.

### 원인 (#166 회귀 — 내 실수)
- #166에서 메인 창에 `onCloseRequested`(미저장 편집 탭 확인)를 달았다. JS close-requested 리스너가 있으면 Tauri가
  네이티브 닫기를 막고(`manager/window.rs`: `has_js_listener` → `prevent_close`), JS 래퍼가 `window.destroy()`로 닫는다.
- capabilities에 `core:window:allow-close`만 있고 **`core:window:allow-destroy`가 없어** destroy가 ACL에서 거부 →
  미저장 여부와 상관없이 X·Alt+F4가 아무 일도 안 함. macOS도 같지만 ⌘Q(자체 종료 항목 → process:allow-exit)는 동작해 덜 드러났다.
- #166 검증 때 실제 앱 창 확인을 못 해(Orca 접근성 차단) 놓쳤다. 목 백엔드 헤드리스 화면 확인은 권한 ACL을 거치지 않는다.

### 수정
- `core:window:allow-destroy` 추가.
- `src/capabilities.test.ts`: 프런트가 쓰는 API(onCloseRequested/destroy, close, setFocus, plugin-process)에 맞는 권한이
  capabilities에 없으면 실패. 권한을 빼면 실패하는 것 확인.

### 검증 (실제 앱 — 이번엔 접근성 자동화가 동작)
- 격리 HOME·식별자(`com.oopnwow.wowterminal.uitest`)로 고치기 전/후 디버그 번들을 만들어 Orca로 닫기 버튼을 눌렀다.
  같은 절차로 각 2회: **수정 전 X → 앱 그대로(2/2), 수정 후 X → 종료(2/2)**.
- 미저장 파일이 있으면 X → 미저장 확인 창 → "저장 안 함" → 앱 종료, 파일은 디스크에서 그대로(`hello`).
- npm test 43(+2 skipped).
- 처음 몇 번은 수정 후 빌드도 닫히지 않았는데, 창을 앞으로 가져오지 않고 낡은 요소 번호로 누른 절차 문제였다
  (같은 절차로 맞춘 뒤 전후가 명확히 갈림).
